# Opt-in synthetic SMS race acceptance

**Before running, the operator must independently verify that the Core and its Postgres, workers, integrations, and all connected devices are isolated staging.** A literal loopback address does not prove isolation: proxies and forwarded ports can reach production. No real device may be connected. The fake peer 12345 may be a real short code outside this isolated setup. The script starts no service and uses no hardware; only the socket client is synthetic. It cannot itself verify deployment or database identity.

Use a dedicated staging admin token and fresh binding code supplied securely. Set CORE_STAGING_SMS_RACE_OPT_IN=yes, CORE_STAGING_ORIGIN to exactly http://127.0.0.1:PORT or http://[::1]:PORT, CORE_STAGING_ADMIN_TOKEN, and CORE_STAGING_BINDING_CODE in the process environment. From core run `node scripts/staging-sms-race.mjs`. Never put secrets in command arguments, source, history, or logs; clear the environment afterwards. Do not run as ordinary tests. Server-side logs are outside this harness's control.

The harness binds a unique synthetic device, sends a heartbeat and authoritative synthetic ready SIM snapshot and checks its correlated ACK and listing. It posts exactly one SMS and buffers socket frames before the HTTP response. After verifying the command against that task, it sends a fake sent result and waits for its positive correlated ACK, sends the identical envelope (same ID and timestamp) and waits for another positive ACK, then verifies the task remains dispatched before issuing the command ACK. It waits for persisted sent via the authenticated idempotency read, sends a distinct fake failed result, checks its ACK and waits for unknown/SMS_RESULT_CONFLICT. A five-second monotonic budget starts before the POST; if it expires, no subsequent race frame or command ACK is sent and the run fails inconclusively. This conservative window is shorter than the dispatcher ACK deadline but cannot prove that the ACK won the server-side race; the observed sent state shows eventual replay only. Read polling is bounded; all write operations and frames are sent once except the intentional identical event replay. This verifies only observed server-side simulation, not actual SMS delivery. The separate happy-path harness remains unchanged.

Finally it closes the socket and attempts one soft revocation of any known synthetic device, checking authenticated GET returns 404. A lost response or interruption may leave unknown bind, SMS, event or revocation outcomes; do not blindly retry. Inspect staging manually. Revocation leaves records, task and idempotency state. Cleanup failure is reported, and a failed bind with no known device ID requires manual inspection. Responses, errors and secrets are suppressed; the operator must manage server logging separately.
