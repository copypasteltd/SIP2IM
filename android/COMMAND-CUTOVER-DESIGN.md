# Android 命令身份迁移设计（未启用）

当前短信与其他命令分别在 `gateway.db` 和 `command_ledger.db` 中去重，同一命令 ID 跨类型可重复接受；旧账本只保留最近 500 条，已经淘汰的历史不可恢复。生产代码没有统一命名空间。

## 切换前条件

- 所有 Service、Activity、接收器及回调必须经同一迁移入口；证明旧进程、旧版本及其他写入者均已停止，且在提交期间不能再次写入。独立 helper 的同步锁不是进程间围栏。
- 缺失或损坏的旧库、恢复/清除数据后的来源不明，以及旧版本仍可能启动的情况均不得被解释成全新安装。新安装需要可信的注册代次和服务端围栏；尚无该实现。
- 不得仅复制数据库主文件并忽略 WAL/journal，不得依赖跨数据库写入的崩溃原子性。先冻结源并读取一致快照，只在目标 gateway.db 中做单事务写入，保留原始源。

## 目标事务

目标表应以命令 ID 唯一约束保存类型、原始规范化版本、请求身份、结果和来源。事务内保留短信/outbox 数据，复制完整可读旧 ACK 与配置，记录来源快照，再合并命名空间：跨账本同 ID、缺失类型/内容或无法比较的旧数据一律隔离；同事务写入迁移状态。任何异常、磁盘写入失败或进程在提交前退出均回滚。提交后不得让旧 APK 再写旧库或直接降级。

SMS 命令 ID 预留、任务建立和应答必须同一数据库事务；配置变更与其应答同事务。排队短信的选择与 claim 都应排除隔离 ID；已领取的短信保持未知、不自动重发，迟到回执仅作为证据记录。现有两种 payload 规范化方式不同，历史记录必须保留来源版本，不重新解释为等价。

## 未解决及验证

Python SQLite 模型仅验证所声明假设下的本地事务；它不能证明 Android 的进程替换、SQLite 实现、旧写入者静止、真实电源中断、配置迁移或任务隔离。现有 Android 源码尚未接入此设计。需完成 Android 真机或授权测试环境中的崩溃恢复、碰撞、回调、磁盘错误、升级/降级及服务端代次围栏测试后，才能选择可运行的迁移路径。
