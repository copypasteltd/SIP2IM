## 3. 目录

| 路径 | 用途 |
|---|---|
| /opt/voip-gateway/core | 核心服务与前端静态文件 |
| /opt/voip-gateway/adapters/qq、/opt/voip-gateway/adapters/telegram | 适配器（Telegram 含 Python venv） |
| /etc/voip-gateway/config.toml | 配置（端口、数据库连接、默认值），0600 |
| /var/lib/voip-gateway/adapter-qq/、adapter-telegram/ | 平台 session，0700 |
| /var/lib/postgresql/14/voip | PostgreSQL 数据目录（由 pg_createcluster 创建） |
| /run/voip-gateway/adapter-qq.sock、adapter-telegram.sock | 两个适配器 socket，0600 |

全部属 root；PostgreSQL 进程沿用既有 postgres 系统用户运行（PostgreSQL 不允许以 root 运行数据库进程，此为既有用户，不新增）。

## 4. 部署步骤（用户已一次性授权安装；每次执行前仍输出完整命令清单）

1. `pg_createcluster 14 voip --port 47432 --start`，监听仅 127.0.0.1；创建数据库 voip 与数据库角色 voip（数据库内角色，非系统用户）。
2. 安装 core 到 /opt/voip-gateway/core，写入 config.toml，执行数据库迁移。
3. 在服务器终端执行 `voip-core admin:create` 设置管理员账号。
4. 安装 systemd 单元并启动。
5. 安装 adb、PulseAudio、Linux QQ 官方客户端、QQ 协议端、Telegram 适配器 Python 依赖；启用两个适配器单元与 Shizuku 自启单元。

## 5. systemd 单元（root 运行）

| 单元 | 说明 |
|---|---|
| voip-core.service | Restart=on-failure；依赖 postgresql@14-voip.service |
| voip-adapter-qq.service | QQ 通道 |
| voip-adapter-telegram.service | Telegram 通道 |
| voip-shizuku-autostart.service | 监视 USB 连接的网关手机，重启后经 adb 启动 Shizuku |

两个适配器同时运行；来电只转给设置中的来电平台。

## 6. 浏览器麦克风安全上下文

项目不配 TLS。内网测试：在测试电脑 Chrome 打开 `chrome://flags/#unsafely-treat-insecure-origin-as-secure`，填入 `http://192.0.2.10:47860`；你搭好 HTTPS 代理后改用代理地址。

## 7. 运维要点

- 日志 journald，不记录凭据；业务内容原样存数据库。
- 无备份（C-09）；磁盘写满时 PostgreSQL 停止写入，服务报错。
- 升级：停服务 → 替换程序 → 迁移 → 启动。
- 网关手机充电线接服务器 USB 口，重启后由服务器自动启动 Shizuku；首次需在手机上允许该服务器的 USB 调试授权。
