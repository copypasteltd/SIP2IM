# 08 测试与验收计划

> 版本 1.2 · 2026-11-20 · 测试设备：努比亚 Z20（唯一真机） · 原则：本地回执与帧计数不算通过，必须双方真人听测

## 1. 门槛

| 门槛 | 目标 | 通过标准 | 不通过 |
|---|---|---|---|
| **G0 设备** | Z20：能力等级、Shizuku、延迟接听、外拨、下行、上行、早期媒体 | TC-G0-01～08 | 上行失败即该机无法语音；由用户决定是否更换测试机或仅交付短信与管理 |
| **G1 浏览器外拨** | 手机⇄核心⇄浏览器 | TC-WEB | 调整缓冲/重采样 |
| **G2 Telegram** | x86_64 用户账号一对一主动语音 + 双向 PCM | TC-TG-01～04 | 换 T-B 路线 |
| **G3 QQ** | x86_64 一对一主动语音 + 双向 PCM | TC-QQ-01～04 | 按 Q-A → Q-B → Q-C 换方案继续 |
| **G4 规模** | 1 台真机 + 设备模拟器（tools/device-simulator，纯软件，非安卓模拟器）20 台以上 | TC-SCALE | 优化后复测 |

G2 与 G3 同步推进，QQ 优先投入。TC-TG-01～04 与 TC-QQ-01～04 的定义见 [开发约束文档 12 §7](开发约束文档/12-测试与质量规范.md)。

## 2. G0 用例（努比亚 Z20）

| 编号 | 步骤 | 期望 |
|---|---|---|
| TC-G0-01 | 手机充电线接服务器；重启手机 | 服务器自动启动 Shizuku；APK 上报能力等级与探测明细 |
| TC-G0-02 | 测试手机拨入，APK 不接 | 主叫持续回铃；20 秒后拒接；主叫侧从未接通 |
| TC-G0-03 | 拨入后命令接听 | 蜂窝 active；服务器录到对方朗读，可辨认 |
| TC-G0-04 | 服务器播放测试音 | 主叫方听到；本机听筒/麦克风无泄漏 |
| TC-G0-05 | 服务器命令外拨 | 对方振铃，接听后双向如 03/04 |
| TC-G0-06 | 外拨期间（对方接听前）采集下行 | 记录能否采到运营商回铃；采不到时确认服务器循环播放“接通中”，两种结果都记录 |
| TC-G0-07 | 连续通话 15 分钟 | 无断流，记录延迟与漂移 |
| TC-G0-08 | 双卡分别重复 03–05 | 记录各卡结果 |

## 3. 功能用例（摘要）

| 编号 | 场景 | 期望 |
|---|---|---|
| TC-DEV-01～10 | 绑定码正常/过期/重复、解绑、断网离线、状态完整、登记号码、重装、通话默认关闭、暂停开关、重启后自动启动 Shizuku | 符合 01 第 4.1 节 |
| TC-SMS-01～09 | 收发、长短信、断网补传、未知不重发、双卡、速率设置、转发到两个平台、消息命令发短信 | 符合 01 第 4.2 节 |
| TC-WEB-01/03/04 | 浏览器外拨、挂断联动、DTMF | 双向听测通过 |
| TC-IN-01～07 | 来电文本（两平台）+ 来电平台语音、接听后接蜂窝、拒接/超时（含未接提醒）、主叫先挂、来电平台占线、来电平台未配对、隐藏号码 | 未接时蜂窝从未 active；非来电平台不收到语音 |
| TC-OUT-01～10 | 两个平台各自发两种格式、匹配失败、先拨后在来源平台回拨、两种超时、拒绝原因、重复消息、回铃透传或循环“接通中”、三次进度回复 | 符合 05 第 6 节 |
| TC-NUM-01 | 号码解析表（01 第 5 节）逐行 | 结果一致 |
| TC-PAIR-01～06 | 两个通道同时登录、生成码、互加好友后配对与替换、错误锁定、解除、切换来电平台 | 符合 05 第 4 节 |
| TC-ADM-01～05 | 登录与锁定、仪表盘、查询、操作日志、三种语言切换 | 正确 |
| TC-OPS-01 | 逐项触发告警与推送 | 出现、推送、可恢复 |

## 4. 规模用例

| 编号 | 场景 | 期望 |
|---|---|---|
| TC-SCALE-01 | 模拟器 20 台以上设备心跳、短信、状态变化 | 状态正确，CPU < 1 核 |
