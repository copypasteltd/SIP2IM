# 06 Admin 后台设计

> 版本 1.2 · 2026-11-20 · 单管理员 · zh-CN / zh-HK / en

## 1. 页面

| 页面 | 内容 | 操作 |
|---|---|---|
| 登录 | 用户名、密码、语言 | 登录 |
| 仪表盘 | 设备总数/在线/离线、能力等级分布、SIM 数、短信可用、通话可用、通话中；QQ 与 Telegram 通道状态；当前来电平台；未处理告警 | 跳转 |
| 设备列表 | 名称、在线与最后心跳、Android 版本与能力等级、SIM 号码、网络、电量、Shizuku（含是否由服务器自动启动）、暂停、通话开关 | 筛选、生成绑定码 |
| 设备详情 | 硬件与版本、各 SIM、能力探测明细、USB 连接状态、最近事件 | 改名、启停、通话开关、默认 SIM、登记号码、解绑 |
| 短信 | 按会话列出全文；转发状态 | 发送、筛选 |
| 通话 | 记录与每条腿时间线；是否播放过“接通中” | 浏览器外拨、挂断、DTMF |
| 平台通道 | QQ、Telegram 两张卡片：桥接账号、登录状态、语音能力验证、配对用户；“设为来电平台”开关（二选一） | 登录（二维码/验证码）、登出、生成配对码、解除配对 |
| 外呼与短信命令 | 消息原文、来源平台、解析结果、拨出 SIM、目标、状态、全部回复 | 查看 |
| 告警 | 类型、对象、时间、推送状态 | 确认 |
| 设置 | 默认设备、界面语言、机器人与提示语音语言、短信转发开关、短信速率、心跳与超时 | 保存 |
| 操作日志 | 管理员写操作 | 查看 |

生成配对码时页面同时显示配对说明：“请先与桥接账号互加好友（Telegram 需允许其来电），再私聊发送此码”。

## 2. 状态显示规则

- 每个状态带最后更新时间；过期显示“未知”。
- “可通话” = 在线 + 未暂停 + 通话功能开启 + Shizuku 运行 + 上下行探测通过。
- L1/L2 设备不显示通话入口；Android 4.4–5.x 设备标注“未实机验证”。
- 号码显示来源标签；SIM 变更标记“需复核”。
- 平台通道分别显示：已登录、消息可收、语音可拨（已验证）、已配对、是否来电平台。

## 3. 多语言

react-i18next，语言包 zh-CN、zh-HK、en；后端返回错误码与告警类型代码，前端翻译；机器人回复模板与“接通中”提示语音按设置语言选择；APK 使用 values / values-zh-rHK / values-en。

## 4. 实时更新与浏览器通话

/ws/admin 推送设备、通话、短信、告警；断线 5 秒重连并全量刷新。浏览器外拨需要麦克风安全上下文（07 第 6 节）。

## 5. 告警

| 告警 | 触发 | 推送 |
|---|---|---|
| 设备离线 | 90 秒无心跳 | 两个配对用户 |
| Shizuku 停止 | 设备上报；自动启动失败时升级 | 两个配对用户 |
| SIM 异常 | 非 ready 持续 60 秒 | 两个配对用户 |
| 短信权限缺失 | 设备上报 | 两个配对用户 |
| 平台通道异常 | logged_out / offline / banned | 另一个仍可用的通道 |
| 通话失败 | 失败或 UNKNOWN 结束 | 两个配对用户 |

同一告警 30 分钟内只推送一次。
