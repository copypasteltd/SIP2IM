## 2. 目标与约束

目标是以 Android 专机作为 SIM 网关、服务器统一管理短信与浏览器/QQ/Telegram 语音。蜂窝来电应保持振铃，直到目标用户应答且媒体就绪才接听；拒绝/超时不得误接听。外拨需要按号码选 SIM 并桥接到来源平台。详见 [需求规格](01-需求规格说明.md) 和 [接口契约](开发约束文档/05-接口契约实现细则.md)。

既有约束：无 SIP，项目 MIT、不复制 GPL/AGPL；本机不使用 Docker、WSL 或安卓模拟器；优先 LAN、单管理员、Android minSdk 19，设计面向多设备。未知发送/提交结果不能盲目重发。用户此前授权 local-server 隔离部署和验收，但本轮明确要求停止；真实短信、电话、账号和对外部署必须确认具体目标及授权。

## 3. Android 网关

已有绑定/凭据、前台服务、WebSocket、心跳、SIM 快照、短信接收/发送、SQLite outbox、命令持久预留及结果回传等源码。绑定有不确定结果标记，异常不盲目重绑，但依赖本地存储语义，完整身份迁移和恢复仍缺。见 [Android 说明](../android/README.md)。

调试包 minSdk 19、targetSdk 34。Shizuku 13.1.5 API 声明最低 API 24，provider 通过资源在低版本默认关闭、v24 开启，调用隔离在 API 24 helper；只核验构建产物中的 manifest/资源，未验证低版本系统启动或 API24+ Binder。当前 call.dial/answer/reject/hangup/dtmf 不做实际电话控制，见 [GatewayService](../android/app/src/main/kotlin/io/voipgw/gateway/core/GatewayService.kt)。

入站 SMS 真实订阅/槽位提取不完整，旧设备 slot 0 是假设；服务未运行时事件可滞留队列，自动唤醒的身份与终止围栏未完成。原始 PDU 未完整保全。详见 [入站归属](../core/SMS-INCOMING-ATTRIBUTION.md)。

## 4. Core、数据与短信

Core 已有 Fastify/TypeScript、共享协议、迁移、认证、绑定、SIM、短信队列、事件、状态、分页与管理 API 等代码。电话事件、拒接意图、媒体帧/路由/重采样/抖动缓冲仅是基础，并不等于可通话；电话创建、平台腿、媒体、计时器、恢复、通知和完整锁尚未完成，见 [通话状态](../core/src/calls/INCOMPLETE.md)。现有代码不应被假定为多实例安全；启动会迁移及协调所连接数据库。

设置条件写曾在隔离服务器验证成功、旧值冲突和恢复。其锁是协作式，旧无条件写/直接 SQL 不受相同 CAS 保护；ABA 不可检测，未知提交后单次读取不能证明最终结果。见 [设置并发](settings-concurrency.md)；该文末“仅 fake 测试”为旧描述。

出站 SMS 模拟验收覆盖任务创建、模拟命令 ACK 和合成 sent；另覆盖结果早于 ACK、精确事件重放及冲突转 unknown。没有真实运营商提交或送达验证；unknown 不等于未发送，禁止盲重试。见 [发送不确定性](17-sms-dispatch-uncertainty.md)。入站模拟事件和精确重放获 ACK，复用 ID 变内容在 FIFO 屏障前未获 ACK，历史仅一条且 simId 为空。此结论不覆盖真实物理广播、断线重启或 SIM 归属。

**未修复：** NUL、孤立 UTF-16 代理项或 parts 超出数据库 int4 等异常入站可能导致现有 PostgreSQL 写入失败及 FIFO 阻塞。编码/事务/审计/会话锁均为未接线原型，不改变生产 ACK，不可声称已完成恢复。见 [异常入站设计](sms-nul-ingestion-design.md)。

## 5. 平台与 Web

QQ 有接口与 IPC 基础，真实登录、消息与语音能力声明为不支持；见 [QQ 能力声明](../adapters/qq/src/backend.ts)。Telegram 可选 Telethon 私聊、手机号/验证码和可选二次密码流程有源码，但只用 fake 测试，session 仅内存、断开期间不排队，QR/语音不支持；配置文件加载及自动拒接来电也未实现，不能假定来电会被处理；见 [Telegram 说明](../adapters/telegram/README.md) 和 [平台身份契约](14-平台消息身份待验证契约.md)。Core 通道能力受限，不能把候选库或页面当作真实账号联通。

Web 已有登录、仪表盘、设备、短信、通道、通话记录、设置等页面和测试，见 [Web 路由](../web/src/app/router.tsx)。呼叫控制 API 仍返回 CAPABILITY_UNSUPPORTED，真实浏览器完整业务未验收。

## 9. 异常短信实验与欠缺

[隔离编码](../core/src/devices/sms-quarantine-envelope.ts)、[实验写入](../core/src/db/sms-quarantine-writer-experimental.ts)、[实验 SQL](../core/experimental/sms-quarantine-prototype.sql)、[实验读取器](../core/src/db/sms-quarantine-reader.ts)均未接入生产。候选方案以 device_event 全局主键及事务保存版本化 bytea 子记录和无内容告警；仍需完整性/不可变权限、旧新版本混跑、告警消费、受权导出、修复重放、保留政策和失败恢复。

编码保留协议解析后的 JS 数值与 UTF-16 码元，不是原始 JSON、数字 token 或 PDU；设备身份必须另行比较。在可发现、可恢复和验证完整之前，不可凭实验原型向旧设备 ACK。
