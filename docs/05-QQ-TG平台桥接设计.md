# 05 QQ / Telegram 平台桥接设计

> 版本 1.2 · 2026-11-20 · 两个通道同时运行；QQ 优先开发 · QQ **待 G3**，Telegram **待 G2**

## 1. 通道模型

| 项目 | 规则 |
|---|---|
| 通道数量 | 最多 2 个：QQ、Telegram，可同时登录运行 |
| 配对用户 | 每个通道 1 个；新配对替换该通道旧配对 |
| 来电平台 | 设置项 inbound_platform（qq / telegram），语音来电只转给它的配对用户 |
| 短信转发 | 发给两个通道的配对用户（可关闭） |
| 来电与未接提醒、告警 | 发给两个通道的配对用户 |
| 外呼与短信命令 | 两个配对用户都可发起；回拨走消息来源平台 |
| 并发 | 每个通道同一时间 1 通语音 |
| 来电平台不可用 | 来电不应答，不自动改转另一平台，提醒发给仍可用的通道 |

## 2. 平台前提与路线

| 项目 | QQ（优先） | Telegram |
|---|---|---|
| 账号 | 专用普通 QQ 号（已准备） | 专用普通用户账号（已准备） |
| 登录 | Linux QQ 官方客户端扫码 | 手机号 + 验证码（+ 二步密码） |
| 消息 | 客户端协议端（NapCat 类，独立进程） | Telethon（MIT） |
| 一对一语音 | 客户端内置音视频 | 原生通话库（ntgcalls，许可证待核实） |
| 好友要求 | 配对用户须与桥接账号互为好友 | 配对用户须将桥接账号加为联系人，并在隐私设置中允许其来电 |
| 网络 | — | 服务器可直连 Telegram，无需代理 |

### 2.1 QQ 推进路线（做不出来就换方案继续）

| 顺序 | 方案 | 进入下一方案的条件 |
|---|---|---|
| Q-A | Linux QQ 客户端 + 协议端收发消息 + 自研 MIT 注入宿主调用客户端音视频模块，音频经 PulseAudio 虚拟设备（软件） | x86_64 上无法发起或接听私聊语音 |
| Q-B | Linux QQ 客户端 + 界面自动化（Xvfb + 无障碍接口）拨号/接听，音频仍走虚拟设备 | 界面无法可靠识别通话状态 |
| Q-C | 一台安卓网关手机运行 QQ 安卓客户端，无障碍服务控制，音频经 Shizuku 采集/注入 | 都不可行时记录并报告 |

### 2.2 Telegram 路线

T-A：Telethon + ntgcalls（独立进程）。T-B：Telegram 官方开源通话库自行封装（许可证待核实）。

## 3. 适配器统一要求

- 两个独立进程、各自 systemd 单元，root 运行；各自 Unix socket（04 第 4 节）。
- capabilities 由适配器如实报告；core 是否向该通道路由语音由 voice_verified 决定（G2/G3 通过后由管理员置为 true）。
- 本文状态机中的大写状态名仅为示意，canonical 状态名见开发约束文档 06 §4 与 08 §3.7。
- “connected”必须来自平台真实接听事件。
- session 目录 `/var/lib/voip-gateway/adapter-qq/`、`/var/lib/voip-gateway/adapter-telegram/`，0700。

## 4. 配对流程

```text
管理员 → 选择平台 → 生成配对码（8 位，5 分钟，单次）→ 连同“先加好友”说明交给用户
用户 → 与桥接账号互加好友/联系人（Telegram 允许来电）→ 私聊发送 8 位码或“绑定 12345678”
core → 码有效且属于该平台 → 原子标记已用 → 撤销该平台旧配对并通知 → 写入新配对 → 回复“配对成功”
```

错 5 次（10 分钟内）锁 30 分钟；群聊、转发忽略；非配对用户的其他私聊不回复。

## 5. 来电转接状态机

```text
NEW → CELL_RINGING → NOTIFIED → PLATFORM_DIALING → PLATFORM_CONNECTED → ANSWERING → BRIDGED → ENDING → ENDED
                                   └─(拒接/超时 20 秒/离线)→ REJECTING → ENDED   （蜂窝从未应答，两边发未接提醒）
来电平台不可用/占线/未配对 ────────────→ REJECTING → ENDED
任意 → UNKNOWN（对账后进入 ENDED，不重拨）
```

| 步骤 | 动作 |
|---|---|
| 1 | call.incoming → 取设备锁 → 检查来电平台：已登录、已配对、空闲、语音能力已验证 |
| 2 | 向两个配对用户发“来电：号码（设备/SIM）”（隐藏号码显示“未知号码”） |
| 3 | 取来电平台通道锁 → 适配器 call.dial → 计时 20 秒 |
| 4 | connected → 复核蜂窝仍 ringing → 设备 call.answer |
| 5 | 蜂窝 active → 两路音频 → BRIDGED |
| 6 | 任一侧结束 → 结束另一侧 → 释放锁 |

主叫先挂 → 立即结束平台腿；平台接听后蜂窝接听失败 → 立即结束平台腿；本机人工接听 → 结束平台腿。

## 6. 消息外呼与短信命令

### 6.1 外呼

```text
MSG_RECEIVED → PARSED → DEVICE_RESERVED → CELL_DIALING(早期下行采集) → PLATFORM_DIALING(来源平台)
  → 用户接通：转发早期媒体 / 循环“接通中” → 被叫接通 → BRIDGED → ENDING → ENDED
```

| 情况 | 处理 | 回复 |
|---|---|---|
| 开始拨号 | 设备 call.dial ack 后，来源平台回拨用户 | “正在用 SIM xxx 拨打 yyy” |
| 用户接通、被叫未接 | 早期媒体可用则转发，否则循环“接通中” | — |
| 被叫先接、用户未接 | 15 秒内用户未接即结束蜂窝；被叫此间听到静音 | “对方已接听，正在回拨你” / “回拨未接听，已挂断” |
| 用户先接、被叫 30 秒未接 | 结束两侧 | “对方未接听” |
| 被叫忙/拒接/失败 | 结束平台腿 | 可确认原因 |
| 设备占用/离线、来源通道正在通话、号码非法 | 不拨号 | 拒绝原因 |
| 通话结束 | — | “通话结束，时长 mm:ss” |
| 重复投递 | 按 message_id 只执行一次 | — |

### 6.2 短信命令（P1）

“短信 <号码表达式> <内容>”，号码表达式同外呼。设备与 SIM 选择规则同外呼；回复“已发送 / 失败 / 未知”。

回复与提示语音按设置语言（zh-CN / zh-HK / en）。

## 7. 账号风险

只用专用账号；QQ 客户端注入与自动化有封号风险；账号 banned / logged_out 时告警。来电平台失效时来电不应答，不自动切换。
