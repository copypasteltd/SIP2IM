# Lossless SMS ingestion and U+0000: proposed design

Status: design only; a standalone parsed-envelope classifier/codec prototype and unit tests exist, but ingestion, migration, operator visibility, ACK changes and PostgreSQL integration remain unwired and unverified.

## Current path and problem

`SmsReceiver` decodes each broadcast PDU, assembles decoded bodies and places the result in an `sms.received` JSON payload; the original PDU bytes are not retained ([receiver](../android/app/src/main/kotlin/io/voipgw/gateway/sms/SmsReceiver.kt), [assembly](../android/protocol/src/main/kotlin/io/voipgw/protocol/SmsParts.kt)). The SQLite outbox keeps SMS events without an expiry, and the gateway sends the oldest event with one in flight, removing it only on a matching positive ACK ([outbox](../android/app/src/main/kotlin/io/voipgw/gateway/core/Outbox.kt), [gateway](../android/app/src/main/kotlin/io/voipgw/gateway/core/GatewayService.kt), [pacer](../android/protocol/src/main/kotlin/io/voipgw/protocol/OutboxPacer.kt)).

Core inserts the parsed payload into `device_event.payload` (`jsonb`) and the SMS body into `sms_message.body` (`text`) in a single transaction ([events](../core/src/devices/events.ts), [schema](../core/migrations/0001_init.sql)). PostgreSQL cannot represent U+0000 in either type; serializing the character as JSON `\u0000` does not make it valid for `jsonb`, which interprets the escape. The session sends a positive ACK only when event processing succeeds and closes with 1011 on an exception ([session](../core/src/ws-device/session.ts)). A poison event can therefore remain at the head of the outbox and block later events. This is a code-path assessment, not an observed deployment result.

## Proposed custody and encoding

1. Deploy Core support first. Detect unsupported database strings before any JSONB or text write, including all payload string fields, not just `body`. Preserve the received event in a versioned, explicitly tagged representation in `bytea` or an ASCII-safe encoded envelope; never write a decoded NUL into PostgreSQL text or JSONB. Do not treat a display replacement as the authoritative value.
2. Specify the exact preservation domain. To round-trip decoded Java/Kotlin and JavaScript strings including isolated surrogates, define a codec over UTF-16 code units, such as little-endian two-byte code units without a BOM, with strict validation, length and encoding version. Avoid implicit UTF-8 conversions that can replace unpaired surrogates. The storage model must also preserve every relevant payload field and metadata. Exact original PDU bytes are a separate guarantee: capture ordered PDU byte arrays and format at the Android receiver, durably, including decode/assembly failures. Legacy rows cannot reconstruct PDUs already discarded.
3. In one transaction, authorize the device, establish event identity and content, durably insert the normal event and downstream notification or a recoverable quarantine record. A positive ACK means that durable custody committed, including quarantine when that meaning is explicitly part of the contract. No ACK on storage failure, rollback or uncertain commit; retry the same ID and content. Compare authoritative representation, device, type and timestamp on duplicate IDs; acknowledge an exact committed duplicate, reject a conflict. Ensure uncertain commits and lost ACKs converge without duplicates or overwrites.
4. Quarantine must retain recoverable bytes, version, identity, reason and repair state. Restrict access, alert operators, record inspection and reprocessing, and provide idempotent replay. Define retention and an authorized disposition; never silently expire or delete before verified repair or that disposition. Storage exhaustion must surface and prevent ACK rather than discard data. Existing outbox rows must remain intact across migration and recover on reconnect.
5. Update all consumers, including SMS history, read repository and admin notification outbox, to decode outside PostgreSQL or expose a tagged lossless representation. Define how legacy clients see exceptional data: an explicitly marked projection with access to the authoritative bytes, never an unmarked substitute. Peer fields, searches and downstream integrations need the same review.

## Compatibility and rollout

- **Old Android → new Core:** accept existing v1 payloads and encode or quarantine them before database insertion, including events already queued. This is the principal recovery path for the blocked FIFO.
- **New Android → old Core:** default to legacy behavior until the server explicitly advertises support. Unsupported new types or versions must fail closed and remain queued. An optional encoded field beside a placeholder `body` is unsafe: the current v1 object schema strips unrecognized fields, allowing old Core to persist and ACK the placeholder ([protocol](../packages/protocol/src/device.ts)). A new event type may block the old FIFO, so disclose the incompatibility and retain data until a capable Core is available.
- **New Android → new Core:** negotiate an explicit capability and version, and bind ACK semantics to durable custody. Upgrade Core before enabling the sender representation. On downgrade, capability loss, reconnect or process restart, never reinterpret a previously sent event under another encoding or change its identity/content without a migration contract.
- The existing receiver returns early for malformed/missing PDUs, addresses or bodies and assembly failures. End-to-end no-drop cannot be claimed solely from a Core change. Define durable capture and recovery for those cases, and distinguish application custody from the platform's own delivery guarantees.

## Candidate shared-identity migration (not implemented)

Retain `device_event.id` as the single cross-type unique arbiter. An additive `custody_kind` discriminator can mark quarantine parent rows while preserving legacy rows as normal; create the authoritative bytea child and durable operator alert in the same transaction. On conflict, perform a subsequent read at READ COMMITTED after the unique-index wait and compare the authenticated device, event type, timestamp and decoded validated canonical payload. A missing or malformed child must fail closed. The marker, stored encoding version, access control, bounded export and repair mechanism all require separate review and real-PostgreSQL tests before any ACK behavior is enabled.

Deploy schema, compatible readers and accessible operations before enabling writes across all replicas. Old readers or workers may not understand quarantine records; do not roll back to them while records or retries remain without a tested compatibility procedure. Existing input is parsed JSON, not original PDU bytes, and the codec does not establish delivery or radio-level custody.

## Capacity and operational gaps

The WebSocket server sets `maxPayload: 65536` bytes ([main](../core/src/main.ts)). Base64, UTF-16 and envelope metadata increase frame size; calculate limits using actual serialized bytes, including worst-case characters. For data that cannot fit, retain locally and surface an actionable condition, or design bounded durable chunking with stable event/chunk identities, checksums, deduplication, atomic reassembly, quotas, and a final ACK only after recoverable custody. Define local and server capacity, backpressure, alerts, retry scheduling and operator repair. None of these guarantees is established by this design alone.

## Verification plan

Use real PostgreSQL integration tests for leading, embedded, trailing and repeated U+0000; a literal backslash-u escape; problematic peer and nested strings; BMP and supplementary characters; and isolated surrogates. Verify exact code-unit round trips and collision-free encoding. Test original PDU byte and ordered multipart preservation separately, including decode failures.

Exercise old/new Android and Core combinations, missing or stale capability, old queued events, unsupported representations and downgraded servers. Inject rollback, failed and uncertain commits, lost ACK, disconnect/restart, identical retries and conflicting IDs. Verify no false ACK, no duplicate side effects, recoverable quarantine and replay, later-event progress after repair, retention and full-disk failures. Test frame sizes at and beyond the actual limit, chunk ordering, corruption and incomplete assemblies. Unit mocks alone cannot establish PostgreSQL behavior or device delivery guarantees.
