# 03 Android 网关设计

> 版本 1.2 · 2026-11-20 · 单 APK，minSdk 19 · 通话音频**待 G0（努比亚 Z20）** · 关联：[协议](04-协议与接口规范.md)

## 1. 为什么通话音频原先要求 Android 13（限制原因）

| 能力 | 所需系统条件 | 原因 |
|---|---|---|
| 读取通话双方声音（下行） | 特权权限 CAPTURE_AUDIO_OUTPUT；普通应用拿不到 | 系统源码对通话音频源（VOICE_DOWNLINK/VOICE_CALL）要求该权限 |
| 把声音送进通话（上行） | Android 13 新增的“通话音频重定向”系统接口；13 以下**没有公开或系统级上行注入接口** | 13 以下只能尝试把音频路由到通话发送设备（TELEPHONY_TX），是否可行完全取决于厂商音频 HAL |
| 以特权身份运行代码 | Shizuku（以 shell 身份运行） | Shizuku 本身不支持 Android 6 以下；Android 11 以下没有无线调试，重启后必须连电脑 ADB 启动 |
| 程序化接听来电 | Android 8.0 起 TelecomManager.acceptRingingCall | 8.0 以下需要隐藏接口和特权 |
| 双卡选择 | Android 5.1 起 SubscriptionManager | 5.1 以下只有厂商私有接口 |

结论：**Android 4.4 可以兼容，但只能做到短信网关；越新的系统能力越完整。** 采用单 APK + 运行时能力分级。

## 2. 能力分级

| 等级 | Android 版本 | 可用能力 | 不可用 |
|---|---|---|---|
| L1 短信 | 4.4–5.0（API 19–21） | 短信收发（主卡可靠，双卡厂商私有接口尽力）、状态、心跳 | 双卡标准接口、通话接管 |
| L2 短信 + 双卡 | 5.1（API 22） | + 双卡标准收发 | 通话接管 |
| L3 呼叫控制 | 6.0–7.1（API 23–25） | + 外拨（指定 SIM）；Shizuku 可用时以 shell 身份接听/挂断 | 通话音频（尽力探测） |
| L4 呼叫控制 + 旧式音频 | 8.0–12（API 26–32） | + 标准接听/挂断；音频走旧式路线：shell 身份采集下行 + 尝试路由到 TELEPHONY_TX 上行 | 上行注入**取决于厂商 HAL，必须实测** |
| L5 完整 | 13+（API 33+） | + 通话音频重定向系统接口（上下行） | 仍需机型实测 |

APK 启动时检测 API 级别、Shizuku 状态与能力探测结果，上报最高可用等级；Admin 只对通过 G0 的设备开放通话功能。

## 3. 努比亚 Z20 评估

| 项目 | 情况 |
|---|---|
| 芯片 | 骁龙 855（高通平台，音频 HAL 常带通话录音/通话播放路由，属有利因素） |
| 系统 | 出厂 Android 9，有 Android 10 升级（以实机为准） → **L4 级** |
| Shizuku | Android 10 及以下无无线调试；手机充电线接 Local-server USB 口，服务器检测到重启后自动经 ADB 启动（ADR-019） |
| 呼叫控制 | 标准接口可用，预期可行 |
| 下行音频 | 以 shell 身份采集 VOICE_DOWNLINK，预期可能可行 |
| 上行音频 | 无 Android 13 接口；需验证能否路由到通话发送设备。**这是 G0 最大不确定项** |
| 结论 | 短信与呼叫控制可行；语音功能取决于 G0 上行测试 |

## 4. 模块划分

| 模块 | 职责 |
|---|---|
| app | 引导、绑定、权限、Shizuku 状态、暂停开关、多语言 |
| core | WebSocket 连接（OkHttp 3.12，支持 API 19）、认证、心跳、命令分发、本地事件队列（SQLiteOpenHelper） |
| sms | 短信接收与合并、按订阅或主卡发送、回执 |
| telephony | 来电/去电状态、接听、挂断、拨号、DTMF；按 API 级别选择实现 |
| privileged | Shizuku UserService：通话音频采集与注入（L4/L5 两种实现）、电话控制兜底 |
| media | 20 ms 帧切分、抖动缓冲、外呼期间的早期下行音频采集 |

## 5. Android 4.4 兼容实现要点

- 单 APK：minSdk 19、targetSdk 34（Android 14+ 拒绝安装 targetSdk < 23 的应用，故 target 必须高）。
- 依赖版本：只选支持 API 19 的版本（如 OkHttp 3.12.x、androidx.core/appcompat 的 API 19 兼容版本）；不用 Room，用 SQLiteOpenHelper；开启 multidex。
- 权限：API 23 以下安装时授予；23 以上运行时申请。
- 后台：API 26+ 使用通知渠道与前台服务；API 34 声明前台服务类型；API 23+ 引导关闭电池优化。
- 每个按版本分支的功能都有对应能力探测与上报，不静默失败。
- 不申请默认短信角色，不读写系统短信库，不采集定位、通讯录、IMEI/IMSI/ICCID。
- 本机规则禁止运行安卓模拟器（属虚拟化），Android 4.4–5.x 仅做编译检查与代码审查，标注“未实机验证”。

## 6. 首次安装引导

1. 安装业务 APK；L3 及以上安装 Shizuku。
2. 授权运行时权限（API 23+），关闭电池优化。
3. 启动 Shizuku：Android 11+ 用无线调试；Android 10 及以下把充电线接到 Local-server，首次在手机上允许该电脑的 USB 调试授权，此后由服务器自动启动。
4. 输入或扫描绑定码。
5. 运行能力探测并上报。
6. 手机重启后：USB 接在服务器上的设备由服务器自动重新启动 Shizuku；其他设备需手动启动，期间 Admin 显示“Shizuku 未运行”。

## 7. 通话控制与音频

- **来电：** 上报 call.incoming，等待核心 call.answer / call.reject；APK 不自行接听。
- **外呼：** 按 SIM 拨号；进入拨号状态即开始采集下行音频并以早期媒体标记上传（C-13）。能否在接听前采到运营商回铃取决于网络与机型；采不到时由服务器循环播放“接通中”提示语音，APK 不生成任何声音。
- **音频实现：** 按 AOSP 公开接口独立实现（C-02）；使用 shell 身份归属上下文；本机听筒与麦克风静音；帧计数正常不等于路由正确，验收以双方真人听测为准。
- **本机人工接听：** 上报后核心结束平台腿，不接管。
- **紧急号码：** APK 拒绝拨打。

## 8. 短信

接收：广播 → 识别 SIM（API 22+ 订阅 ID；以下尽力）→ 合并 → 本地队列 → 上传 → 确认后删除。发送：持久化任务 → 分段发送 → 上报状态。

## 9. 连接与可靠性

单条控制 WebSocket，断线指数退避（1～30 秒）；通话时另开音频连接；本地队列至少一次送达，服务端按事件 ID 去重；协议版本不兼容时拒绝连接并告警。
