## 2. 组件职责

| 组件 | 职责 | 不负责 |
|---|---|---|
| 安卓 APK | 短信收发、电话控制、通话音频提取与注入、状态与能力等级上报 | 业务决策 |
| voip-core | 设备认证与连接、短信任务与转发、呼叫状态机、媒体交叉、“接通中”提示播放、Admin API、i18n、持久化 | 平台协议细节 |
| 平台适配器（2 个） | 各自桥接账号登录、私聊收发、原生一对一语音拨打/接听、平台 PCM 读写 | 授权与路由 |
| voip-shizuku-autostart | 监视 USB 连接的网关手机，重启后经 adb 启动 Shizuku | 其他设备管理 |
| Admin 前端 | 多语言管理界面、浏览器麦克风/扬声器 | 业务规则 |

## 3. 技术栈（依赖许可证见 11）

| 层 | 选型 |
|---|---|
| Android | Kotlin；minSdk 19，targetSdk 34；能力分级 L1–L5（见 03） |
| 特权 | Shizuku（Android 6+）；Android 10 及以下由服务器 adb 自动启动 |
| 核心服务 | Node.js 20/22 + TypeScript + Fastify + ws |
| 数据库 | PostgreSQL 14 独立集群 voip，node-postgres |
| 浏览器音频 | WebSocket 二进制 PCM + AudioWorklet |
| 前端 | React + Vite + TypeScript + react-i18next |
| 号码 | libphonenumber-js + 01 第 5 节规则 |
| QQ 适配器 | Linux QQ 客户端 + 自研 MIT 注入宿主（首选），备选链见 05 |

## 4. 音频链路

| 段 | 格式 |
|---|---|
| 手机 ⇄ 核心 | PCM S16LE 单声道 16 kHz（不支持时 8 kHz），20 ms/帧 |
| 浏览器 ⇄ 核心 | PCM S16LE 单声道 16 kHz，20 ms/帧 |
| 适配器 ⇄ 核心 | PCM S16LE 单声道 48 kHz，20 ms/帧 |

**外呼等待音（C-13）：** 设备拨号即采集下行并标记为早期媒体。用户接通回拨后、被叫未接听前，core 每 20 ms 判断：最近 1 秒有早期媒体且能量高于静音阈值 → 转发早期媒体；否则循环播放“接通中”。被叫接听后切换为正常双向音频。

## 5. 呼叫协调与并发

- 设备锁：每台设备同一时间 1 通。
- 通道锁：每个平台通道同一时间 1 通；两平台可各有 1 通。
- 来电只占用来电平台的通道锁；外呼占用消息来源平台的通道锁。
- 浏览器外拨只占设备锁。
- 全系统平台语音并发上限 = 2（QQ 1 + Telegram 1）。

## 6. 部署拓扑

单台 Local-server。voip-core 0.0.0.0:47860；PostgreSQL 127.0.0.1:47432；适配器仅 Unix socket；网关手机经局域网 Wi-Fi 连接，充电线接服务器 USB 口。详见 07。

## 7. 安全边界

- CORS 关闭校验；Admin API 用 Bearer 令牌（ADR-007）。
- 设备独立令牌可吊销；socket 文件权限 0600。
- 配对即生效、外呼无限制（C-10、C-11），盗打风险已接受（RISK-06）。
