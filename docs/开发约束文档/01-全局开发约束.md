# 01 全局开发约束

> 版本 1.0 · 2026-11-20 · 本文所有条目均为强制要求

## 1. 产品硬约束（来自需求文档 C-01～C-16）

| 编号 | 约束 | 对开发的直接含义 |
|---|---|---|
| C-01 | 无 SIP | 禁止引入 pjsip、sofia-sip、JsSIP、SIP.js、Asterisk、FreeSWITCH、Kamailio 等；协议与命名不出现 SIP 语义 |
| C-02 | MIT | 根目录 LICENSE 为 MIT；不复制 GPL/AGPL 代码；参考开源实现只能理解原理后独立编写 |
| C-03 | 免 Root、无外接硬件 | 不调用 su；不依赖蓝牙、外置声卡；可依赖 Shizuku；充电线接服务器 USB 允许 |
| C-04 | 单 APK，minSdk 19 | 一个 applicationId；按 API 级别运行时分支，不出多版本 APK |
| C-05 | ≥ 20 台设备 | 按设备的逻辑不得 O(n²)；连接管理按设备 ID 映射 |
| C-06 | 单管理员、root 运行 | 不做角色权限；systemd 以 root 运行；不创建系统用户（PostgreSQL 沿用既有 postgres 用户） |
| C-07 | 原生部署，禁虚拟化 | 不写 Dockerfile / compose；本机不启用 WSL、不运行安卓模拟器 |
| C-08 | 关闭 CORS 校验、不配 TLS | 对所有来源返回允许跨域；只监听 HTTP；鉴权只走 Authorization 头 |
| C-09 | 永久保存、不脱敏、无备份 | 不写删除业务数据的代码；业务数据原样入库；不实现备份 |
| C-10 | 配对即生效 | 配对码校验通过立即写入配对，无审批状态 |
| C-11 | 外呼无限制 | 不实现外呼频率/次数限制；仅保留设备锁与通道锁 |
| C-12 | 双通道并存，指定来电平台 | 两个适配器同时运行；来电语音只发来电平台；短信与提醒发两边 |
| C-13 | 回铃透传，兜底“接通中” | 唯一允许播放的合成音是“接通中”提示语音 |
| C-14 | +86 / +852 | 号码解析严格按需求文档 01 第 5 节 |
| C-15 | 三语言 | 用户可见文案全部走 i18n，禁止硬编码 |
| C-16 | PostgreSQL | 服务端数据只存 PostgreSQL 14 集群 voip |

## 2. 工程硬约束

| 编号 | 约束 |
|---|---|
| E-01 | 业务规则只写在 core；APK 与适配器只执行命令、如实上报 |
| E-02 | 跨进程消息带唯一 ID（ULID）；改变外部世界的动作（发短信、拨号、接听）带幂等键 |
| E-03 | 状态以“观测时间 + 有效期”表达，过期即“未知”，禁止沿用旧值 |
| E-04 | 结果不确定一律记 `unknown`，禁止自动重试发短信或重拨 |
| E-05 | 协议事实来源优先级：[05 接口契约](05-接口契约实现细则.md) > `packages/protocol/fixtures` > 代码；TS、Kotlin、Python 三端都必须通过同一组 JSON 样例测试 |
| E-06 | 协议时间统一 UTC 毫秒整数；数据库 timestamptz；展示时才转时区 |
| E-07 | 号码内部统一存 E.164；短号原样存并标记 `kind=short` |
| E-08 | 凭据（管理员密码、设备令牌、平台 session、签名密钥）不得进入日志、仓库、测试样例、对话 |
| E-09 | 不得修改、停止、重启 Local-server 上任何非本项目的服务、数据库集群、端口 |
| E-10 | 用户可见文本必须有 zh-CN、zh-HK、en 三份，缺一视为未完成 |
| E-11 | 所有外部调用（设备、适配器、数据库）有超时；超时记 unknown |
| E-12 | 服务端代码同时兼容 Node 20 与 22，不使用 Node 22 独有 API |
| E-13 | 令牌只放请求头或 WebSocket 首条消息，不放 URL；请求日志剔除 Authorization 与 token |
| E-14 | 状态名、错误码、CallCause 只用 05、06 中列出的取值，不自创 |

## 3. 禁止事项清单

- 引入 SIP、WebRTC 服务端组件（ICE/TURN/STUN 服务器）、Docker、WSL、模拟器。
- 复制 KoishiRTC、android-voice-sip-agent 或任何 GPL 项目的源码、注释、常量表。
- 生成除“接通中”以外的任何提示音、回铃音、忙音。
- APK 未收到 `call.answer` 自行接听来电。
- 拨打紧急号码（110、119、120、122、112、999）。
- 编写删除短信/通话记录的接口或任务。
- 在代码、文档、样例中写入真实账号、密码、手机号、令牌。
- 未经确认对真实号码拨号或发短信；自动化测试中连接真实 QQ / Telegram 服务器。

## 4. 允许的自主决策范围

**无需请示：** 内部命名、文件拆分、私有工具函数、测试数据构造、日志措辞、10 号设计规范范围内的 UI 微调、02 白名单内依赖的小版本。

**必须请示：** 与 01～16 或需求文档不一致的做法；白名单外依赖；协议字段变化；已发布表结构变化；任何服务器操作；任何真实通话、短信、账号登录。

## 5. 真实世界操作的授权流程

1. 在工作日志写出：动作或命令、目标（服务器路径/号码/账号）、预期结果、回滚方式。
2. 向用户展示，等待明确同意。
3. 执行后记录实际结果与证据。

已一次性授权（需求文档 12 R16）：在 Local-server 安装本项目所需软件并新建 PostgreSQL 集群 voip。每次执行前仍须列出命令。

## 6. 完成定义（Definition of Done）

任务同时满足以下全部条件才能标 `DONE`：

1. 代码已提交本地 git，提交信息符合 [03 第 6 节](03-仓库结构与工程规范.md)。
2. 新增/修改代码有单元测试，模块检查命令全部通过（见 12 第 2 节）。
3. 14 中该任务的验收标准逐条满足，工作日志附证据（命令输出、截图路径、测试报告）。
4. 用户可见文本三语齐全。
5. 新依赖已登记 THIRD_PARTY_NOTICES.md 与需求文档 11。
6. 协议、表结构、接口变化已同步到 05、06 与需求文档 04。
7. 14、15 已更新。

## 7. 不确定时怎么办

- 文档没写清：选最保守、可逆的做法，日志标注“假设”，登记到 15 的“待确认”。
- 文档冲突：停止该项，写变更申请。
- 技术上做不到：记录实验过程与证据，标 `BLOCKED`，不换成未授权的替代方案。
