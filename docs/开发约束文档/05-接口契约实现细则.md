# 05 接口契约实现细则

> 版本 1.3 · 2026-11-20 · 本文是需求文档 [04 协议与接口规范](../04-协议与接口规范.md) 的实现级细化并**取代其第 1–5 节**。
> **事实来源优先级：本文 > `packages/protocol/fixtures` > 代码。** 三者不一致时先改本文（需变更申请），再同步 fixtures 与三端代码。

## 1. 通用约定

| 项目 | 规则 |
|---|---|
| ID | 类型前缀 + 26 位大写 ULID，总长 = 前缀长度 + 26。前缀：`dev_` 设备、`sim_` SIM、`sms_` 短信、`tsk_` 短信任务、`ses_` 通话会话、`leg_` 通话腿、`cal_` 呼叫（设备或平台上的单通电话）、`evt_` 设备事件、`cmd_` core 命令、`ipc_` 适配器消息、`req_` 外呼/短信命令请求、`alr_` 告警、`aud_` 操作日志、`pmg_` 平台消息 |
| 时间 | 协议中 UTC 毫秒整数；数据库 timestamptz |
| 号码 | 字段 `number` 为 E.164 或短号原文；附 `numberKind: "e164" \| "short" \| "unknown"`（隐藏号码为 unknown 且 number = null） |
| 枚举 | 小写下划线 |
| JSON 字段名 | 协议与 API 一律 camelCase；数据库一律 snake_case；repo 层负责转换 |
| 未知字段 | 忽略（向前兼容） |
| 缺必填字段 | 回 `ack{ok:false,error:"BAD_MESSAGE"}` |

## 2. 设备绑定（HTTP，无需登录）

```text
Admin 生成绑定码 → 手机输入 6 位码或用系统相机扫二维码（打开 voipgw://bind 深链接）
→ APK 调用 POST /api/device/bind → 获得 deviceId 与设备令牌 → 连接 /ws/device
```

| 项目 | 内容 |
|---|---|
| 二维码内容 | `voipgw://bind?host=192.0.2.10&port=47860&code=012345` |
| 请求 | `POST http://<host>:<port>/api/device/bind`，body `{ code, manufacturer, model, apiLevel, apkVersion, apkCode, locale }` |
| 成功 200 | `{ data: { deviceId, token } }`；token 为 32 字节随机 Base64url，**只返回这一次** |
| 失败 | 400 `BINDING_INVALID`（不存在/已使用）、410 `BINDING_EXPIRED`、429 `BINDING_RATE_LIMITED`（同一 IP 每分钟 > 10 次） |
| 原子性 | 校验与标记已用在同一事务内；同一码并发提交只有一个成功 |

## 3. 设备控制通道 `/ws/device`

### 3.1 连接与认证

1. 连接 `ws://<host>:47860/ws/device`。
2. 5 秒内发送 `hello`（携带设备令牌），否则关闭码 4001。
3. 令牌无效 4003；设备已解绑 4010；设备已禁用 4011（禁用设备不可连接）；协议主版本不兼容 4005（并产生告警 `protocol_mismatch`）。
4. 同一设备新连接成功后，旧连接以 4009 关闭。
5. 通过后 core 回 `hello.ok`；设备随即发送 `status.snapshot`，再冲刷 Outbox。

吊销规则：解绑时 core 立即以 4010 关闭现有连接；此后该令牌再次连接返回 4003。

### 3.2 信封

```json
{ "v": 1, "type": "<type>", "id": "evt_…|cmd_…", "ts": 1794700000000, "payload": {} }
```

- 设备发出的事件 id 前缀 `evt_`，**在事件写入 Outbox 时生成并固定**，重发时不变；core 以此 id 去重（device_event.id、sms_message.event_id 均等于此 id）。
- core 发出的命令 id 前缀 `cmd_`。

### 3.3 设备 → core

| type | payload | 进入 Outbox | core 回 ack |
|---|---|---|---|
| `hello` | `{ token, apkVersion, apkCode, protocol: 1, manufacturer, model, apiLevel, locale }` | 否 | 否（回 hello.ok） |
| `heartbeat` | `{ battery: 0–100\|null, charging: bool\|null, network: "wifi"\|"cellular"\|"none"\|"unknown", signalDbm: int\|null, shizuku: "running"\|"stopped"\|"not_installed"\|"unsupported"\|"unknown", paused: bool }` | **否**（断线期间丢弃） | 否 |
| `status.snapshot` | `{ sims: Sim[], simsAuthoritative?: bool, capabilityLevel: "L1".."L5", probes: Probes, permissions: Perm[] }` | 否（每次连接与变化时重新生成） | 是 |
| `sms.received` | `{ subId\|null, slot\|null, from, fromKind, body, receivedAt, parts }` | 是，永久保留直到 ack | 是 |
| `sms.result` | `{ taskId, state: "sent"\|"failed"\|"delivered"\|"unknown", errorCode\|null }` | 是 | 是 |
| `call.incoming` | `{ callId, subId\|null, slot\|null, from\|null, fromKind }` | 是，**TTL 60 秒**（过期未发出即丢弃） | 是 |
| `call.state` | `{ callId, state: CellCallState, cause: CallCause\|null }` | 是，TTL 60 秒 | 是 |
| `ack` | `{ refId, ok, error\|null }` | 否 | — |

`unknown` 是 v1 的增量枚举，必须先升级所有 Core 接收端，再升级 Android；旧接收端会拒绝该事件，协议没有能力协商，也不可在新 Android 运行时回滚 Core。Android 在跨越系统发送边界前，原子持久化领取和 unknown Outbox 事件（无 TTL，直到成功 ack），不能因此重发短信。迟到的同设备 sent/failed 确证可以解决 unknown，普通的迟到 `unknown` 保留已经确认的结果；同一任务出现相互矛盾的 failed 与 sent/delivered 证据时，无论先后都记为 unknown 且不重发。负命令 ACK 后收到任何设备结果也构成矛盾；Core 持久保存 ACK 来源并保守记为 unknown。`SMS_RESULT_CONFLICT` 是 Core 保留错误码，设备不得发送。拒绝不存在或不属于该设备的任务结果。旧 Android 仍兼容新 Core。 Android 按原绑定、连接代次、任务和分段匹配发送回执。`unknown/SMS_PARTIAL_SEND` 记录多分段的部分成功，可由独立的确定结果对账。仅当同一分段的原申领回执互相矛盾时，设备才报告 `unknown/SMS_CALLBACK_CONFLICT`，另用新的事件 ID。Core 持久化原事件并将任务投影为不可被普通回执覆盖的 `unknown/SMS_RESULT_CONFLICT`。每次精确重放沿用原 ID、时间和载荷。升级时先部署可识别矛盾证据的 Core。

心跳中 `unknown` 表示对应状态无法可靠观测：不得将其解释为网络断开或 Shizuku 已停止。`none` 仅表示已确认无网络；`stopped` 仅表示已确认停止。管理端 Device.status 中相应字段也可取 `unknown`。兼容部署顺序：先更新 core、管理端及其他消费者以接受新枚举，确认部署完成后设备才可发送 `unknown`；旧设备继续发送原有枚举。

`simsAuthoritative` 仅在完整且可靠地观察到 SIM 清单时为 true；缺省或 false 表示清单可能不完整。仅 true 时，core 将清单未包含的现役 SIM 状态置为 unknown，不退役、不删除历史或人工号码；空数组也遵守该规则。固定阈值（当前不可配置）：设备时间戳早于服务器当前时间 2 小时或超过未来 5 分钟的快照仅保存事件，不更新状态，也不阻塞后续快照；有效窗口内不晚于先前有效快照的事件同样仅保存。SIM 的新鲜度按观测时间计算（未来时间最多按服务器当前时间计算），超过 2 小时不能用于发送；设备时钟偏差仍可能导致暂缓更新。 Android 获取不到 SIM 清单时仍可上报短信权限，使用 `sims=[]` 和 `simsAuthoritative=false`。现有 SIM 记录继续按原观测时间自行过期。

当前 Android `sms.received` 的 `subId` 始终为 null；`slot` 在 API < 22 时由设备端假定为 0，在 API ≥ 22 时为 null，二者均不是从短信广播提取的元数据。Android 公开的 `SMS_RECEIVED_ACTION` 文档列出 `pdus` 和 `format`，不能将 `SMS_DELIVER_ACTION` 的其他字段视为该广播的保证。Core 保存设备事件中的原始 payload，但新入站短信的 `sim_id` 始终为 null，不据此归属 SIM。

**Sim：** `{ slot, subId\|null, carrier\|null, state: "ready"\|"absent"\|"locked"\|"unknown", reportedNumber\|null, mcc\|null, mnc\|null }`
**Probes：** `{ smsSend, smsReceive, dial, answer, hangup, dtmf, downlink, uplink, earlyMedia }`，每项 `{ result: "ok"\|"fail"\|"untested"\|"unsupported", probedAt, detail\|null }`
**Perm：** `{ name, granted }`
**CellCallState：** `ringing`、`dialing`、`alerting`（对方振铃）、`active`、`disconnected`

### 3.4 core → 设备

| type | payload | 设备 ack 何时回 | ok:false 的情况 |
|---|---|---|---|
| `hello.ok` | `{ deviceId, serverTime, config: { heartbeatSec, locale } }` | 不回 | — |
| `sms.send` | `{ taskId, subId\|null, slot, to, body }` | 任务已写入本地库后 | DEVICE_DISABLED（暂停中）、SMS_PERMISSION_MISSING、SIM_NOT_READY |
| `call.dial` | `{ callId, subId\|null, slot, to, media: MediaLeg }` | 校验通过、媒体连接已发起、拨号已提交后 | DEVICE_DISABLED、DEVICE_BUSY、NUMBER_EMERGENCY、CAPABILITY_UNSUPPORTED、CALL_PERMISSION_MISSING |
| `call.answer` | `{ callId, media: MediaLeg }` | 媒体连接已发起、接听已提交后 | CALL_NOT_RINGING、CAPABILITY_UNSUPPORTED |
| `call.reject` | `{ callId }` | 拒接已提交后 | CALL_NOT_RINGING（已结束时也回此码，core 视为成功） |
| `call.hangup` | `{ callId }` | 挂断已提交后 | CALL_NOT_FOUND（core 视为成功） |
| `call.dtmf` | `{ callId, digits }`（0–9 * #） | 已发送后 | CALL_NOT_ACTIVE、CAPABILITY_UNSUPPORTED |
| `probe.run` | `{ items: string[] }` | 立即 | — |
| `config.update` | `{ heartbeatSec?, locale? }` | 应用后 | — |
| `ack` | `{ refId, ok: true, error: null }` | — | — |

**MediaLeg：** `{ sessionId, legId, path: "/ws/media?session=<ses>&leg=<leg>", format: 2 }`（format 为 core 期望格式，设备若不支持可降为 1，见 §4.3）。

**暂停（只能在手机本机切换）：** 暂停期间设备照常心跳与上传短信；对 `sms.send`、`call.dial`、`call.answer` 回 `ok:false, DEVICE_DISABLED`；来电仍上报 `call.incoming`，core 见 heartbeat.paused=true 时直接下发 `call.reject`。

### 3.5 可靠性规则

- ack 是统一格式 `{refId, ok, error}`，**表示接收与前置校验结果**；动作的最终结果另以事件报告（sms.result、call.state）。
- core 等待设备 ack 10 秒：超时则该命令结果为 `unknown`，**改变外部世界的命令（sms.send、call.dial、call.answer）绝不重发**；call.reject / call.hangup 可重发至多 2 次（幂等）。
- 设备对重复的 cmd id 直接回上次的 ack，不重复执行（保留最近 500 个）。
- core 对重复的 evt id 直接回 ack，不重复处理。
- core 收到已结束会话的 call.state 只记录事件，不改变会话状态。

### 3.6 CallCause 枚举（设备与适配器共用）

`remote_hangup`（对方挂断）、`local_hangup`（本端按命令挂断）、`rejected`（对方拒接）、`busy`、`no_answer`、`unreachable`（关机/不在服务区/号码无效）、`network_error`、`local_answered`（手机上人工接听）、`privacy_blocked`（平台隐私设置拒绝来电）、`not_friend`（平台要求好友关系）、`timeout`（core 计时器到期）、`cancelled`（主叫在接通前挂断）、`unknown`。

## 4. 媒体通道 `/ws/media`

### 4.1 连接与认证

| 接入方 | 何时连接 | 认证 |
|---|---|---|
| 设备 | 收到 `call.dial` / `call.answer` 后立即，按 MediaLeg.path | 请求头 `Authorization: Bearer <设备令牌>`；core 校验该腿属于此设备 |
| 浏览器 | `POST /api/calls` 返回后立即 | 连接后**首条文本消息** `{"type":"auth","token":"<mediaToken>"}`；mediaToken 一次性，仅此腿有效 |
| 适配器 | 不使用 WebSocket，见 §5 | — |

5 秒内未认证关闭码 4401；认证失败 4403；腿不存在或已结束 4404；被同腿新连接替换 4409。令牌不得出现在 URL 中（避免进入请求日志）。

### 4.2 帧格式（小端，二进制消息）

| 偏移 | 长度 | 字段 | 取值 |
|---|---|---|---|
| 0 | 1 | version | 1 |
| 1 | 1 | format | 1 = PCM16 8 kHz，2 = PCM16 16 kHz，3 = PCM16 48 kHz（均单声道） |
| 2 | 1 | flags | bit0 早期媒体；bit1 服务器提示语音；bit2 静音帧（无 PCM 数据） |
| 3 | 1 | reserved | 0 |
| 4 | 4 | seq | uint32，回绕 |
| 8 | 4 | captureTs | 毫秒 uint32，回绕 |
| 12 | n | pcm | 20 ms：format1 = 320 字节，2 = 640，3 = 1920；静音帧 n = 0 |

### 4.3 格式协商

- 每条腿的格式在**该腿第一帧**确定，之后不得改变（改变即断开该腿，记 media_format_changed）。
- 设备：优先 format 2，构造失败降为 1。core 向设备发送的帧使用与设备上行相同的格式。
- 浏览器：固定 format 2。适配器：固定 format 3。core 内部统一 16 kHz，负责全部重采样。

### 4.4 时序规则

- 每 20 ms 一帧；无声可发静音帧。
- 接收端抖动缓冲目标 80 ms（60～120 自适应），积压 > 300 ms 丢最旧帧。
- 连续 2 秒无帧 → 事件 `media_stalled`（不自动结束通话，状态由信令决定）。
- 单腿每分钟解析失败 > 50 次 → 断开该腿并告警。

## 5. 适配器 IPC（Unix socket）

### 5.1 传输

- core 为服务端：`/run/voip-gateway/adapter-qq.sock`、`/run/voip-gateway/adapter-telegram.sock`，权限 0600。每个 socket 同一时间只接受一个适配器连接，新连接替换旧连接。
- 帧：`[4 字节大端 uint32 长度 L][1 字节类型][L-1 字节内容]`，**L 包含类型字节**，上限 1 MiB。
- 类型 0x01 = JSON 控制消息（UTF-8）；类型 0x02 = 音频：`[1 字节 audioChannel][§4.2 帧，format = 3]`。
- 需求文档 04 第 4 节的“换行分隔 JSON”已作废。

### 5.2 控制消息信封与回执

`{ "v": 1, "type", "id": "ipc_…", "ts", "payload" }`。**每条控制消息都要求对方回 `ack{refId, ok, error}`**（ack 本身除外），超时 10 秒。改变外部世界的命令（message.send、call.dial）超时记 unknown，不重发。

### 5.3 消息

| 方向 | type | payload | 说明 |
|---|---|---|---|
| A→C | `adapter.hello` | `{ platform, adapterVersion, protocol: 1 }` | 连接后首条 |
| A→C | `capabilities` | `{ login, sendMessage, receiveMessage, dial, receiveAudio, sendAudio, maxConcurrentCalls }` | 如实报告；core 是否路由由 voice_verified 决定 |
| A→C | `account.state` | `{ state: AccountState, selfId\|null, alias\|null, detail\|null }` | |
| A→C | `login.step` | `{ step: "qr"\|"phone"\|"code"\|"password", qrPngBase64\|null, hint\|null }` | core 转推 /ws/admin |
| A→C | `message.received` | `{ platformMessageId, senderId, senderName\|null, chatType: "private"\|"group"\|"channel", forwarded, isContact: bool\|null, text, ts }` | |
| A→C | `call.state` | `{ callId, state: "dialing"\|"ringing"\|"connected"\|"ended"\|"failed", cause: CallCause\|null }` | connected 只能在对端真实接听后发出 |
| A→C | `call.incoming.rejected` | `{ fromUserId, ts }` | 有人直接呼叫桥接账号：适配器**自动拒接**并报告，core 只记录 |
| C→A | `account.login` | `{}` | 开始登录 |
| C→A | `account.login.submit` | `{ step, value }` | 手机号 / 验证码 / 二步密码；value 不得写日志 |
| C→A | `account.logout` | `{}` | |
| C→A | `message.send` | `{ userId, text }` | ack 中 ok 表示平台已接受 |
| C→A | `call.dial` | `{ callId, userId, audioChannel }` | audioChannel 0–255 由 core 分配，通话结束后回收 |
| C→A | `call.hangup` | `{ callId }` | |
| 双向 | `ack` | `{ refId, ok, error\|null }` | |

**AccountState：** `logged_out`、`login_pending`、`logged_in`、`offline`、`banned`、`error`。需求文档中的 need_login 等同 logged_out。

## 6. Admin REST API

### 6.1 通用

- 前缀 `/api`；JSON；鉴权 `Authorization: Bearer <token>`（`/api/auth/login`、`/api/device/bind`、`/api/health` 除外）。
- 成功 `{ "data": … }`；失败 `{ "error": { "code", "message", "details" } }`；message 为英文调试信息，前端按 code 翻译。
- 列表：`?cursor=&limit=50`（≤ 200），响应 `{ data: [], nextCursor: string|null }`，按时间倒序。
- `Idempotency-Key` 头：`POST /api/sms`、`POST /api/calls` **必填**，缺失返回 400 IDEMPOTENCY_KEY_REQUIRED；同键重复请求返回首次结果。
- CORS：任意 Origin 均回 `Access-Control-Allow-Origin: <Origin>`、`Access-Control-Allow-Headers: Authorization, Content-Type, Idempotency-Key`、`Access-Control-Allow-Methods: GET,POST,PUT,PATCH,DELETE,OPTIONS`；预检 204（C-08）。
- 请求日志中必须剔除 Authorization、Idempotency-Key 头与任何 token 参数。
- `GET /api/sms/idempotency` 需要 Bearer 鉴权与原样 `Idempotency-Key` 请求头（非空且最多 256 字符），不接受查询参数；200 返回 `{ "data": <与 POST 相同的出站短信及嵌套 task>|null }`，响应带 `Cache-Control: no-store`。缺失或空白键返回 400 `IDEMPOTENCY_KEY_REQUIRED`，过长或查询参数返回 400 `BAD_REQUEST`。仅返回 origin=admin 的出站短信；键是全局命名空间而非每用户独立（当前单管理员），其他来源或非出站记录不会在此接口中披露，因而也会返回 `null`。该操作只读取已提交数据，不发送、领取或触发队列；`null` 仅是读取时的观察，原请求仍可能随后提交，不能据此断定不会发送。不要将键放入 URL、日志或审计记录。

分页按 `(first_at,id)` 降序，服务器返回的游标保留 PostgreSQL 微秒并绑定 `state`。只传 `cursor` 时每页 50 条；新管理端总是传 `limit`。响应形状不变。不带 `limit` 或 `cursor` 的旧请求仍读取全部匹配记录，使用 `nextCursor: null`。游标不是跨请求快照，状态变化或新增记录应回最新页核对。确认只从 `open` 变为 `acked`，不修改 `resolvedAt`。会话凭据和管理员在写事务内复核，同一事务保存 `alert.ack` 审计；不存在或不再开放为 404。提交或清理结果需要核对时返回 503 `TIMEOUT_UNKNOWN`，应单独读回记录，不自动重复确认。

通话详情的 events 当前不分页、不截断；事件量很大时数据库聚合及响应序列化可能消耗大量内存和时间。

SIM 条件更新将读取到的 `number` 原样作为 `expectedNumber`（无号码时为 `null`）；服务器在 SIM 锁内比较当前值，只有相等才写入规范化后的新号码。此值比较无法发现号码先变化后恢复的 ABA，也无法发现号码相同但来源变化。旧接口仍无条件写入。

升级顺序：先更新 Core，再更新 Web。旧 Core 不支持条件接口，返回 404；Web 显示保存失败且不会降级到旧接口。404 也可能表示 SIM 已不存在，不能仅凭状态码断言必须升级。

**当前 Core 实现的兼容性说明：** 心跳和超时离线扫描只发送 `device.updated`，包括在线、离线状态变化；这些路径目前不发送 `device.online` 或 `device.offline`。两种事件名仍保留在协议中，但不保证发送、顺序或持久投递。仅监听 online/offline 的消费者会漏掉变化，必须监听 `device.updated` 并重新读取设备状态。该事件只是尽力发送的失效提示；数据快照可能过期或乱序，应在收到提示及重连后重新查询。禁用或撤销也不保证发送 presence 状态变化事件。若需要完整有序的变化记录，仍需持久化、版本化事件流及消费者支持。

- 客户端每 25 秒发 `{"type":"ping"}`，服务器回 `{"type":"pong"}`。
