# 2026-11-21 工作日志 / Maintenance log

## 媒体接收时序和断流 / Media timing and stalls

- Core 在接收与播放时使用单调时钟。设备鉴权前缓冲的帧保留原到达时间，满 5 秒不能再通过鉴权；超过 300 ms 的帧不播放。
- 抖动缓冲至多保留 15 个序号槽，拒绝重复或已错过播放位置的帧。长间隔后在向前推进的序号上重新缓冲，兼容回绕。
- 两条已认证且仍获授权的通话腿各自检查 2 秒收帧中断。诊断不记录 PCM 或凭据，也不主动挂断或重拨。
- A receiver-side monotonic clock preserves original arrivals. The existing five-second authentication cutoff is checked directly. Buffered frames older than 300 ms are dropped. The sequence window remains bounded and can re-prime on forward progress after a gap, including across wraparound.
- Each authorized attached leg is checked independently. Rejected duplicates or late frames do not reset the stall clock. Stall diagnostics do not disclose audio or credentials, cause a hangup, or trigger another dial.

- 961 Core tests passed and six skipped, including 67 passing focused media and call regressions. All 182 Web tests and 12 synthetic demo smoke tests passed. Type checks, builds, Web lint and locale-key parity passed. Both retained motion assets decoded end to end.
- 未接触真机、实际 SIM、平台账号或生产服务。结果不证明蜂窝双向音频、端到端时延或 PostgreSQL 实库行为。浏览器本地“监听”也不是已认证媒体流或双向音频的证据。
- No physical device, SIM, live account, or production service was used. These results do not establish two-way cellular audio, end-to-end latency, or PostgreSQL behavior. The browser’s local listening status does not independently establish an authenticated media stream or working duplex audio.
