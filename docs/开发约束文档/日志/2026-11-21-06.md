# 2026-11-21 工作日志 / Maintenance log

## 通话启动对账与预约回收 / Call restart recovery and reservation sweep

- Core 先获得独占所有权，再以每事务最多 64 条会话进行启动对账。未确认提交后不继续启动；已确认批次保留。不会自动挂断或重拨。
- 浏览器拨号认领在取得锁后，按数据库时钟核对 30 秒预约期限。独立巡检每次最多检查 16 条过期记录；只有原始创建、身份、两条未使用的腿及无尝试等证明一致时，才结束会话。锁冲突待后续轮转，未知 Web 会话保留占用。
- Core reconciles at most 64 locked sessions per startup transaction under exclusive ownership. An unconfirmed commit stops subsequent batches. Recovery does not hang up or redial.
- Browser reservations expire at the database cutoff. The background sweep checks up to 16 expired candidates and closes only positively proven unarmed sessions. Unknown Web calls continue to block a new dial; denied arming does not send a command.

- 949 Core tests passed and six skipped; 182 Web and 12 demo tests passed. Type checks, builds, Web lint, and locale-key parity passed. Both unchanged motion assets decoded end to end.

- New cases use offline database and transport fixtures. Live PostgreSQL locking and query plans, process-manager restart, and physical-device acceptance remain unverified. No real account, device, or SIM was used, and no new calling capability was enabled.
