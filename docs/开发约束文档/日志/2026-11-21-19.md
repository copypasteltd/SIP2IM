## QQ 与 Telegram 的 IPC 上报回执截止 / QQ and Telegram IPC report ACK deadlines

- 上报从本地写入开始计 10 秒。只有当前连接、原上报 ID 且在截止前处理的匹配 ACK 才有效。关闭或取消时清理原连接的等待，不让旧连接结算新上报，也不重放。
- Telegram 将 `drain()` 与 ACK 限制在同一窗口，启动取消也排空对原连接的本地等待。已写入报文不能由超时或取消推断为未处理。Core 账号控制迟到存证与平台能力不变。
- Each outgoing report gets a ten-second monotonic window from the local write. Only a matching current-link ACK processed before the cutoff is eligible. Closure and cancellation retire original waits without replay or replacement-link settlement.
- Telegram uses the same budget for `drain()` and its ACK, and cancels and joins local waits when startup is cancelled. A timeout does not prove that a written frame was not processed. Core late-evidence handling and supported capabilities are unchanged.
