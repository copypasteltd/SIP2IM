# 03 仓库结构与工程规范

> 版本 1.0 · 2026-11-20

## 1. 位置

- **仓库根目录 = `./`**（本地目录名 VOIP，对外发布名 voip-gateway）；`docs/` 即仓库文档，随代码一起入库与开源。
- 工具链：`VOIP/.toolchain/`（JDK、Android SDK、Node 22、Gradle 缓存），**不入库**（.gitignore）。
- 门槛证据：`VOIP/evidence/`，**不入库**（含录音与真实号码）。
- 归档草案 `docs/archive/` 入库，仅供追溯。

### 2.1 npm 工作区包名（命令中统一用路径形式 `-w <目录>`）

| 目录 | package.json name | 示例命令 |
|---|---|---|
| packages/protocol | @voipgw/protocol | `npm run -w packages/protocol check` |
| core | @voipgw/core | `npm run -w core check` |
| web | @voipgw/web | `npm run -w web check` |
| adapters/qq | @voipgw/adapter-qq | `npm run -w adapters/qq check` |
| tools/device-simulator | @voipgw/device-simulator | `npm run -w tools/device-simulator start -- --count 25` |
| tools/audio-probe | @voipgw/audio-probe | `npm run -w tools/audio-probe start` |
| tools/shizuku-autostart | @voipgw/shizuku-autostart | `npm run -w tools/shizuku-autostart build` |

每个工作区必须提供脚本：`build`、`lint`、`typecheck`、`test`、`check`（= lint + typecheck + test）。根目录 `npm run check` 依次执行全部工作区的 check。

## 3. 命名规范

| 对象 | 规范 | 示例 |
|---|---|---|
| TS 文件 | kebab-case | `call-coordinator.ts` |
| TS 类型/类 | PascalCase | `CallSession` |
| TS 函数/变量 | camelCase | `reserveDevice` |
| 常量 | UPPER_SNAKE | `HEARTBEAT_TIMEOUT_MS` |
| Kotlin 包 | `io.voipgw.gateway.<模块>` | `io.voipgw.gateway.sms` |
| Python 包 | snake_case | `voipgw_tg` |
| 数据库表/列 | snake_case，表名单数 | `call_leg.session_id` |
| 协议 type | 小写点分 | `call.incoming` |
| 错误码 | 大写下划线 | `DEVICE_OFFLINE` |
| i18n 键 | 点分，页面前缀 | `devices.list.empty` |
| 环境变量 | `VOIPGW_` 前缀 | `VOIPGW_CONFIG` |

## 4. 代码风格

- TS：prettier（printWidth 100、单引号、分号）；eslint 启用 `no-floating-promises`、`no-explicit-any`、`consistent-type-imports`。
- Kotlin：官方风格 + ktlint。
- Python：ruff + black，类型注解必填，mypy strict。
- 单文件 > 400 行须拆分；注释写“为什么”。

## 5. core 模块分层

| 文件 | 职责 | 可依赖 |
|---|---|---|
| `types.ts` | 模块内类型 | protocol |
| `repo.ts` | 唯一访问数据库处 | db |
| `service.ts` | 业务逻辑 | repo、其他模块 service（单向，见 08 依赖图） |
| `routes.ts` | HTTP 路由，只校验参数并调用 service | service |
| `*.test.ts` | 测试 | 全部 |

禁止：routes 直接查库；循环依赖；service 中拼 HTTP 响应。

## 6. git 规范

- 分支：`main` 为可用基线；任务分支 `task/<TODO编号>-<简述>`。单人推进可直接在 main 上按任务提交。
- 提交信息：`<类型>(<范围>): <说明> [<TODO编号>]`，类型 feat / fix / test / docs / refactor / chore / build。例：`feat(sms): 发送任务幂等处理 [C-SMS-03]`。
- 每个提交可编译、测试通过。
- 禁止提交：`.toolchain/`、`evidence/`、`config.toml`（只提交 example）、签名密钥、session、`node_modules`、`build/`、`dist/`、录音、含真实号码的文件。

## 7. 配置与日志

- 配置：`/etc/voip-gateway/config.toml`，可由 `VOIPGW_CONFIG` 覆盖；启动时 zod 校验，缺项打印字段后退出。
- 日志级别 error / warn / info / debug，默认 info；每条带 `module`，通话相关带 `sessionId`，设备相关带 `deviceId`。
- 禁止输出密码、令牌、session、配对码明文。短信正文与号码仅 debug 级输出。

## 8. 错误处理

- 业务错误抛 `AppError(code, httpStatus, details?)`，code 必须在 05 错误码表。
- 未知异常转 `INTERNAL` 并记录堆栈。
- 外部调用带超时，超时记 `unknown`。
