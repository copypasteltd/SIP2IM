# 13 构建部署与发布流程

> 版本 1.0 · 2026-11-20 · 本机构建 → 上传 Local-server → root 部署；禁止 Docker/WSL

## 0. 服务器访问方式

- 目标：Local-server，192.0.2.10:22，root 执行（C-06）。
- 凭据：本机 dsh-vault 中条目 **Local-server**（SSH 密码认证）。由能访问该密码库的会话读取；**不得**把密码写入命令行参数、脚本文件、日志、文档或对话。已验证的安全做法：在程序内读取凭据，写入用后即删的临时文件，由 Python paramiko 读取并连接，连接时固定校验主机密钥（ed25519 指纹已记录在本机 known_hosts）。
- 无法访问该密码库的 agent：不得自行寻找凭据，应在日志中列出要执行的命令，交由用户或有权限的会话执行。
- 每次服务器写操作前列出命令并获得用户确认（01 §5）。

## 1. 本机工具链安装（M0，一次性）

| 工具 | 安装位置 | 说明 |
|---|---|---|
| Node.js 22 LTS（Windows zip 版） | `./.toolchain/node` | 不改系统 PATH；脚本中用绝对路径或会话内临时 PATH |
| JDK 17（Temurin zip） | `…\.toolchain\jdk17` | 设置 `JAVA_HOME` 仅在构建脚本中 |
| Android SDK 命令行工具 | `…\.toolchain\android-sdk` | 只装 platform-tools、platforms;android-35、build-tools;35.x；**不装 emulator 与 system-images** |
| Gradle | 由 gradle wrapper 下载到 `…\.toolchain\gradle-home`（`GRADLE_USER_HOME`） | |

安装命令与校验结果写入工作日志。

## 2. 构建

| 产物 | 命令（仓库根目录） | 输出 |
|---|---|---|
| protocol | `npm run -w packages/protocol build` | packages/protocol/dist |
| core | `npm run -w core build` | core/dist（ESM，目标 node20） |

| APK | `android\gradlew -p android :app:assembleRelease` | `android/app/build/outputs/apk/release/app-release.apk` |

## 3. 原生依赖处理

@node-rs/argon2 等带预编译二进制的包需要 linux-x64 版本：发布包中不打包 node_modules，改为在服务器上执行 `npm ci --omit=dev`（服务器已有 npm）。打包时附带 package-lock.json。

## 4. 服务器首次部署（M2 完成后执行，执行前列出命令供确认）

```bash
# 1. PostgreSQL 集群（沿用已有 postgres 系统用户，不新建系统用户）
pg_createcluster 14 voip --port 47432 --start-conf=auto -- --auth-local=peer --auth-host=scram-sha-256
# 修改 /etc/postgresql/14/voip/postgresql.conf: listen_addresses = '127.0.0.1'
systemctl start postgresql@14-voip
sudo -u postgres psql -p 47432 -c "create role voip login"
sudo -u postgres psql -p 47432   # 进入交互后执行：\password voip   （密码不出现在命令行与 shell 历史）
sudo -u postgres psql -p 47432 -c "create database voip owner voip"
sudo -u postgres psql -p 47432 -c "create database voip_test owner voip"

# 2. 目录
mkdir -p /opt/voip-gateway /etc/voip-gateway /var/lib/voip-gateway/adapter-qq /var/lib/voip-gateway/adapter-telegram /run/voip-gateway
chmod 700 /var/lib/voip-gateway/adapter-*

# 3. 程序
mkdir -p /opt/voip-gateway-<版本> && tar -xzf voip-gateway-<版本>.tar.gz -C /opt/voip-gateway-<版本>
ln -sfn /opt/voip-gateway-<版本> /opt/voip-gateway
cd /opt/voip-gateway && npm ci --omit=dev
cp deploy/config.example.toml /etc/voip-gateway/config.toml && chmod 600 /etc/voip-gateway/config.toml
# 编辑 config.toml：数据库密码等

# 4. Telegram 适配器 Python 环境
python3 -m venv /opt/voip-gateway/adapters/telegram/.venv
/opt/voip-gateway/adapters/telegram/.venv/bin/pip install /opt/voip-gateway/adapters/telegram

# 5. 管理员（交互输入密码）
node /opt/voip-gateway/core/dist/cli.js admin:create --username <用户名>

# 6. systemd
cp deploy/systemd/*.service /etc/systemd/system/
systemctl daemon-reload
systemctl enable --now voip-core
systemctl enable --now voip-adapter-telegram      # D-05 时
systemctl enable --now voip-adapter-qq            # D-06 时
systemctl enable --now voip-shizuku-autostart     # D-07 时
```

数据库密码由部署者生成，只写入 config.toml，不写入日志、文档或对话。

## 5. config.toml 结构

```toml
[server]
host = "0.0.0.0"
port = 47860
public_host = "192.0.2.10"      # 用于设备绑定二维码

[database]
host = "127.0.0.1"
port = 47432
database = "voip"
user = "voip"
password = ""                       # 部署时填写

[paths]
assets = "/opt/voip-gateway/core/assets"
web = "/opt/voip-gateway/web/dist"
run = "/run/voip-gateway"

[adapters.qq]
enabled = true
socket = "/run/voip-gateway/adapter-qq.sock"

[adapters.telegram]
enabled = true
socket = "/run/voip-gateway/adapter-telegram.sock"
api_id = 0                          # 用户提供
api_hash = ""                       # 用户提供

[log]
level = "info"

[test]
probe_api = false              # 仅 G0 测试期间临时设为 true（05 §6.5）
probe_answer_inbound = false   # 仅 G0：来电改由 audio-probe 接听
```

## 6. systemd 单元要点

| 单元 | 关键配置 |
|---|---|
| voip-core.service | `ExecStart=/usr/bin/node /opt/voip-gateway/core/dist/main.js`；`Environment=VOIPGW_CONFIG=/etc/voip-gateway/config.toml`；`Restart=on-failure`；`After=postgresql@14-voip.service`；`RuntimeDirectory=voip-gateway`、`RuntimeDirectoryPreserve=yes`（适配器 socket 位于此目录，core 重启时不删除） |
| voip-adapter-telegram.service | `ExecStart=/opt/voip-gateway/adapters/telegram/.venv/bin/python -m voipgw_tg`；`After=voip-core.service` |
| voip-adapter-qq.service | 按 G3 选定路线；Q-A/Q-B 需 Xvfb 与 PulseAudio；QQ 客户端以 `--no-sandbox` 运行；PulseAudio 的 root 运行方式见 09 §3“root 运行要点”；单元内定义 `DISPLAY` 与 `PULSE_SERVER` |
| voip-shizuku-autostart.service | `ExecStart=/usr/bin/node /opt/voip-gateway/tools/shizuku-autostart/dist/main.js` |

全部 `User=root`（C-06）。

## 7. 升级

1. 本机打包新版本。
2. 上传服务器 → `systemctl stop voip-adapter-* voip-core`。
3. 解压覆盖到新目录 `/opt/voip-gateway-<版本>`，切换符号链接 `/opt/voip-gateway`（保留旧版本以便回滚）。
4. `npm ci --omit=dev` → `systemctl start voip-core`（启动时自动迁移）→ 启动适配器。
5. 检查 `/api/health`。

回滚：切回旧符号链接并重启。迁移只增不删，旧版本仍可运行（新增列须有默认值）。

## 8. APK 发布

- 发布签名：首次生成 keystore 存入本机密码库（写入需用户确认），构建时从密码库读出到临时文件、构建后删除。
- 版本号：versionName 语义化版本，versionCode 单调递增。
- 安装：通过服务器 USB 连接执行 `adb install -r`，或复制 APK 到手机手动安装。

## 9. 部署检查清单
