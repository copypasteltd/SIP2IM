# 17 Agent 接入提示词

> 版本 1.0 · 2026-11-20 · 把下面的提示词直接粘贴给新的 agent 作为任务开场。每个推进线一段，按需选用。

## 1. 通用开场（每个 agent 都先给这一段）

```text
你将参与开发一个开源（MIT）项目：多台安卓旧手机作为 SIM 网关，由内网服务器统一管理短信、浏览器通话，以及 QQ/Telegram 原生语音的来电转接和消息触发外呼。

工作目录：./（即 git 仓库根目录）。

开始任何工作前，按顺序完整阅读：
1. docs/开发约束文档/00-入口与阅读指南.md
2. docs/开发约束文档/01-全局开发约束.md
3. docs/开发约束文档/15-推进看板.md
4. docs/开发约束文档/日志/ 中最近 3 份日志
5. docs/开发约束文档/04-开发流程与协作规范.md

硬性规则（违反即任务失败）：
- 不使用任何 SIP 技术；不使用 Docker、WSL、任何虚拟机或安卓模拟器。
- 不复制 GPL/AGPL 代码；新依赖必须在 docs/开发约束文档/02 白名单内，否则先请示。
- 不伪造完成：没运行的测试不写通过；需要真机/真实账号才能验证的任务只能标 REVIEW。
- 真实拨号、发短信、登录 QQ/Telegram、修改服务器之前，先列出具体动作等我确认。
- 不把任何密码、令牌、session、真实号码写进代码、日志、文档或对话。

工作方式：
- 只领取 docs/开发约束文档/14-TODO总表.md 中状态 READY 且依赖全部 DONE 的任务。
- 每个任务按 04 第 2 节七个步骤执行，按 01 第 6 节完成定义验收。
- 修改文件前先读文件；同一错误尝试 3 次仍失败就停下记录，不要盲目重试。
- 会话结束前：更新 14 与 15，并按 16 模板在 日志/ 写交接记录。

现在请先完成阅读，然后告诉我：你理解的当前焦点、你准备领取的任务编号、你的实现计划（不超过 10 行）。得到我确认后再开始写代码。
```

## 2. 推进线专用补充

### 线 1 · 基础骨架

```text
你负责推进线 1：ENV-01～ENV-11、P-01～P-05。
额外必读：docs/开发约束文档/02、03、05、12。
重点：工具链只装到 VOIP/.toolchain，不改系统 PATH；packages/protocol 是三端协议的唯一事实来源，fixtures 必须同时覆盖合法与非法样例。
ENV-10、D-02 涉及服务器，先列命令等我确认。
```

### 线 2 · Android

```text
你负责推进线 2：ENV-07、ENV-08、P-06、A-01～A-18。
额外必读：docs/03-Android网关设计.md、docs/开发约束文档/05、07、10 第 10 节、12。
重点：minSdk 19，每个依赖都要核实支持 API 19 并锁定版本；按 07 第 2 节的版本矩阵实现，业务代码只调用 platform/ 下的接口；APK 绝不自行接听来电；通话音频只按 AOSP 公开接口独立实现。
没有模拟器：JVM 单元测试必须充分；真机测试只在努比亚 Z20 上进行，且需我安排。
```

### 线 3 · Core 服务端

```text
你负责推进线 3：C- 开头的全部任务（按 14 中的依赖顺序）。
额外必读：docs/04、05 号需求文档，docs/开发约束文档/05、06、08、12。
重点：业务规则只在 core；每个状态机转换写 call_event；“平台未接听绝不发送 call.answer”必须有属性测试；结果未知记 unknown，绝不自动重发短信或重拨；配对码与 +852 号码的区分按 08 第 3.10 节；状态名只用 06 §4 的 canonical 取值。
集成测试只读 VOIPGW_TEST_DATABASE_URL（ENV-11）；不能访问服务器时只跑单元测试并把集成测试任务标 BLOCKED，不得连接 voip 以外的集群。
```

### 线 4 · Web 前端

```text
你负责推进线 4：W-01～W-16。
额外必读：docs/06-Admin后台设计.md、docs/13-前端设计规范与原型.md、prototypes/index.html、docs/开发约束文档/10、11、05 第 6 节。
视觉方向 V01 未选定前：只用令牌名开发，theme.css 暂用原型 01；W-15 需等待用户选定。
重点：颜色只用设计令牌；状态必须图标 + 文字；三语齐全且布局不溢出；跳线图是唯一使用动效的元素，并尊重减少动效；不引入完整 UI 套件和任何 CDN 资源。
接口未完成时，用 msw 或本地假数据开发，但不得提交假数据到生产代码路径。
```

```text
- 运行对应检查命令，确认真实通过；
- 核对验收标准与证据是否一一对应；
- 检查是否违反 01 第 1–3 节任一约束；
- 检查三语、许可证登记、协议与文档是否同步。
发现问题：把任务状态改回 DOING 或 TODO，并在日志写明原因与修复要求。
```
