## 1. 本目录是什么

本目录把 [需求与方案文档（docs/00～12）](../00-README.md) 转化为**可直接执行的开发规范**：做什么、按什么顺序做、用什么技术、写成什么结构、怎样才算完成。需求文档回答“系统应该是什么”，本目录回答“怎么把它造出来”。

## 2. 五条黄金规则（违反任何一条即视为任务失败）

1. **不使用任何 SIP 相关技术**，不使用 Docker / WSL / 任何虚拟化（含安卓模拟器）。
2. **不复制任何 GPL / AGPL 代码**；项目代码一律 MIT。新增依赖先查 [02 技术栈](02-技术栈与版本约束.md) 白名单。
3. **不得伪造完成**：未运行的测试不得写“通过”；帧计数、接口返回 200、本地回执都不等于通话成功。
4. **不擅自操作真实世界**：真实拨号、发短信、登录 QQ/TG 账号、修改服务器，都必须先列出具体动作并获得用户确认（见 [01 第 5 节](01-全局开发约束.md)）。
5. **每完成一项任务，必须同步更新** [14 TODO 总表](14-TODO总表.md) 与 [15 推进看板](15-推进看板.md)，并写工作日志。

## 5. 开工标准动作（每次会话都执行）

1. 打开 [15 推进看板](15-推进看板.md)，看“当前焦点”和“下一步”。
2. 读 [日志/](日志/README.md) 中最近 3 份记录。
3. 在 [14 TODO 总表](14-TODO总表.md) 找状态为 `READY` 且依赖全部 `DONE` 的任务。
4. 按 [04 第 2 节](04-开发流程与协作规范.md) 的任务流程执行。
5. 结束前：更新 14、15，用 [16 模板](16-模板集.md) 写工作日志。

## 6. 文档优先级（发生冲突时）

1. 用户在对话中的最新明确指示
2. 需求文档 [01 需求规格](../01-需求规格说明.md) 的硬约束 C-01～C-16
3. 需求文档 [10 决策登记](../10-决策与风险登记.md) 的 ADR
4. 本目录 01 全局开发约束
5. 本目录其他文档
6. 需求文档其他部分
7. 归档草案（只作参考，**不得**作为实现依据）

发现冲突时**不要自行选择**：按 16 模板写变更申请，交用户决定。

## 7. 状态标记

| 标记 | 含义 |
|---|---|
| `TODO` | 未开始，依赖未满足 |
| `READY` | 依赖已满足，可领取 |
| `DOING` | 进行中（注明执行者、日期） |
| `BLOCKED` | 被外部条件阻塞（注明原因与解除条件） |
| `REVIEW` | 已实现，待真机/真实账号验证 |
| `DONE` | 验收标准全部满足且有证据 |
| `DROPPED` | 经用户同意放弃 |
