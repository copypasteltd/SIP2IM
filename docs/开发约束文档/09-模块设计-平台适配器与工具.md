# 09 模块设计 · 平台适配器与工具

> 版本 1.1 · 2026-11-20 · 关联：需求文档 [05](../05-QQ-TG平台桥接设计.md)、本目录 [05 第 5 节](05-接口契约实现细则.md)

## 1. 适配器公共要求

- 独立进程，启动后连接 core 的 Unix socket，发送 adapter.hello、capabilities、account.state。
- 断线 1～30 秒退避重连；core 未启动时等待，不退出。
- 未经门槛验证的能力在 capabilities 中如实报告（能做到就是 true），**是否允许路由由 core 的 voice_verified 决定**。
- session 文件只存本地目录，0700，不写日志。
- 配置来源：与 core 共用 `/etc/voip-gateway/config.toml`，只读取自己的 `[adapters.<platform>]` 段；session 目录 `/var/lib/voip-gateway/adapter-<platform>/`。
- 有人直接呼叫桥接账号时：**自动拒接**，并发送 `call.incoming.rejected`（05 §5.3）。
- 全部以 root 运行（C-06），**禁止为解决权限问题而新建系统用户**；需要的运行参数见第 3 节“root 运行要点”。
- 测试中禁止连接真实平台：用假平台实现（fake）跑单元测试。

## 2. Telegram 适配器 `adapters/telegram`

```text
adapters/telegram/
├─ pyproject.toml                    依赖：telethon、（通话库，待核实）
├─ src/voipgw_tg/
│  ├─ main.py                        入口，读取配置
│  ├─ ipc.py                         与 core 的帧协议
│  ├─ account.py                     登录状态机：phone → code → password
│  ├─ messages.py                    私聊收发、过滤 chatType/forwarded
│  ├─ calls.py                       一对一呼叫：请求、状态映射、挂断
│  ├─ audio.py                       通话库 PCM 收发 ↔ IPC 48 kHz 帧
│  └─ fake_platform.py               测试替身
└─ tests/
```

| 任务 | 说明 |
|---|---|
| 登录 | api_id / api_hash 由管理员在配置文件中提供（Telegram 开发者后台申请，用户操作）；Admin 发起登录 → 适配器推送 login.step(phone) → 管理员提交手机号 → code → 可选 password |
| 消息 | 只处理私聊；isContact 由联系人列表判断并上报 |
| 呼叫 | 发起一对一语音；状态映射：等待 → dialing，对方响铃 → ringing，接受并建立 → connected，结束 → ended |
| 音频 | 通话库输出/输入 48 kHz PCM16，按 20 ms 分帧 |
| 预研（T-SPIKE） | 在本机或服务器 x86_64 上验证：通话库安装、主动一对一呼叫、双向 PCM；产出可运行的最小脚本与结论，写入日志；**真实账号测试需授权** |
| 备选 T-B | T-A 失败时评估 Telegram 官方开源通话库封装，记录许可证与可行性 |

## 3. QQ 适配器 `adapters/qq`

```text
adapters/qq/
├─ package.json
├─ src/
│  ├─ main.ts
│  ├─ ipc.ts
│  ├─ backend.ts                     QqBackend 接口
│  ├─ backends/route-a/              Q-A：协议端 + 自研注入宿主
│  ├─ backends/route-b/              Q-B：界面自动化
│  ├─ audio/pulse.ts                 PulseAudio 虚拟设备读写（parec/pacat 子进程）
│  └─ fake-backend.ts
└─ test/
```

**QqBackend 接口：** `login()`、`logout()`、`onState(cb)`、`onMessage(cb)`、`sendMessage(userId, text)`、`dial(userId)`、`hangup(callId)`、`onCallState(cb)`、`audioIn(): Readable`、`audioOut(): Writable`。路线切换只替换 backend 实现。

| 路线 | 预研任务 | 产出 |
|---|---|---|
| Q-A | Q-SPIKE-A：x86_64 上安装 Linux QQ 官方客户端（固定版本）+ 协议端；验证消息收发；研究以自研代码触发私聊语音与读取通话音频的可行方式（只读公开资料，不复制 GPL 代码） | 可行性结论、所需组件与许可证、最小原型 |
| Q-B | Q-SPIKE-B：Xvfb 下运行客户端，通过 AT-SPI 无障碍接口识别好友列表、语音按钮、接听状态 | 能否稳定识别 dialing/connected/ended |
| Q-C | Q-SPIKE-C：安卓手机运行 QQ，无障碍服务控制 + Shizuku 音频 | 仅 Q-A、Q-B 失败后启动，需用户确认占用手机 |

音频：PulseAudio 创建 `voipgw_qq_sink` / `voipgw_qq_source` 两个 null-sink/虚拟源；客户端麦克风选虚拟源、扬声器选虚拟 sink；适配器用 parec/pacat 以 48 kHz 单声道读写。

**root 运行要点（Q-SPIKE-A 中逐项核实并记录）：**

| 组件 | 问题 | 处理 |
|---|---|---|
| PulseAudio | 默认拒绝以 root 运行 | 先试 `pulseaudio --daemonize=no --exit-idle-time=-1`（root 下以用户模式运行，记录是否被拒绝）；被拒则用 `--system` 模式。注意：apt 安装 pulseaudio 时软件包可能自动创建 `pulse` 系统账户——**这属于软件包行为，安装前须向用户说明并获得确认**，不得自行另建用户 |
| Linux QQ（Electron） | root 下需关闭 Chromium 沙箱 | 启动参数 `--no-sandbox`；运行于 Xvfb 虚拟显示（软件，不属于虚拟化） |
| Xvfb | — | `Xvfb :99 -screen 0 1280x800x24`，适配器单元设置 `DISPLAY=:99` |

## 4. 设备模拟器 `tools/device-simulator`

- 用途：规模测试（≥ 20 台）与无真机时联调。
- 功能：`--count 25 --server ws://… --bind-codes file`；每台模拟 hello、heartbeat、snapshot（1～2 张 SIM）、随机来短信、响应 sms.send 并回结果、模拟来电与外拨状态流转、发送静音或正弦波音频帧。
- 输出：每台设备的事件统计、延迟分布、错误。

## 5. 音频探针 `tools/audio-probe`（G0 用）

- 运行在本机或服务器；通过内部接口 `POST /internal/probe/call`（05 §6.5，仅在配置 `[test] probe_api = true` 时启用）发起外拨，并以浏览器腿角色接入 /ws/media；来电测试时以同样方式接管 web 接听（由测试配置 `[test] probe_answer_inbound = true` 控制，仅 G0 使用）。
- 功能：录制下行音频为 WAV；向上行播放测试音（1 kHz 正弦、朗读数字的预录 WAV）；输出电平、丢帧、延迟报告；生成 G0 证据文件。

## 6. Shizuku 自启 `tools/shizuku-autostart`

- 运行于 Local-server，systemd 单元 voip-shizuku-autostart。
- 每 10 秒执行 `adb devices -l`；每次启动尝试的结果都上报 core（`POST /internal/shizuku-autostart`，payload 见 05 §6.5），对已授权设备检测 Shizuku 是否运行（`adb shell pidof shizuku_server` 或包内启动脚本状态），未运行时执行 Shizuku 官方提供的 adb 启动命令。
- 记录每次启动结果到 journald；连续 3 次失败上报 core（HTTP 内部接口 `POST /internal/shizuku-autostart`，仅允许 127.0.0.1）。

## 7. 提示语音 `tools/prompt-builder`

- 只生成一种提示语：“接通中”（en：“Connecting”），zh-CN、zh-HK（粤语）、en 三个版本；文件名 `connecting.zh-CN.pcm`、`connecting.zh-HK.pcm`、`connecting.en.pcm`；16 kHz 单声道 PCM16 原始数据，时长 1.5～2.5 秒，首尾各 200 ms 静音。
- 合成工具使用 espeak-ng（GPL 工具仅用于生成，不随项目分发；其输出音频不受 GPL 约束）。不使用授权不明的商业语音。
- 产物放 `core/assets/prompts/`，许可证 CC0，在 THIRD_PARTY_NOTICES 中声明为自制素材。
- 管理员可替换同名文件为真人录音。
