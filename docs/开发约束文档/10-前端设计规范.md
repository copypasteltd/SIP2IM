# 10 前端设计规范

> 版本 1.1 · 2026-11-20 · 适用：Admin Web（`web/`）与 APK 界面
> **与需求文档 [13 前端设计规范与原型](../13-前端设计规范与原型.md) 的关系：** 13 定义状态语义、令牌名、10 套视觉方向原型（`prototypes/`）与选型方式；本文定义**与视觉方向无关、必须遵守的**结构、组件、交互、文案与工程规则。
> **视觉方向（V01）尚待用户选型。** 选定前：一律使用 13 §3.7 的令牌名开发，令牌取值暂用原型 01（`prototypes/themes/s01-switchboard.css`）；选定后只替换令牌文件，不改组件代码。

## 1. 使用者与场景

唯一管理员；桌面浏览器长时间挂着监看，偶尔操作；内网。界面的首要任务是**一眼看清哪台设备、哪张 SIM、哪个平台通道是否可用，以及正在进行的通话处于哪一步**。

## 2. 设计令牌（名称固定，取值来自选定主题）

| 令牌 | 用途 |
|---|---|
| --bg / --surface / --surface-2 | 页面底色 / 卡片 / 次级容器 |
| --text / --muted / --line / --line-soft | 正文 / 次要文字 / 分割线 |
| --primary / --primary-ink | 主操作色 / 其上文字 |
| --ok / --warn / --err / --unk / --live | 状态色（第 3 节） |
| --radius / --radius-sm / --chip-radius | 圆角 |
| --font-display / --font-body / --font-mono / --font-num | 标题 / 正文 / 等宽 / 数字 |
| --nav-*（bg、text、muted、hover、active-bg、active-text） | 导航栏 |

规则：

- 组件中**禁止**直接写颜色值、字体名；只能引用令牌。
- 主题文件放 `web/src/styles/theme.css`，内容来自选定原型的 `prototypes/themes/sXX-*.css` 中的 `:root` 变量；原型中的装饰性选择器（如导航圆点样式）作为“主题装饰层”放 `theme-decor.css`，可整体替换。
- 字体：使用主题指定的字体栈；若主题需要非系统字体，只允许 OFL 许可字体并本地自托管（不使用 CDN）。
- 对比度：正文 ≥ 4.5:1；大字与图标 ≥ 3:1。替换主题后必须重新核对。

## 3. 状态语义（与需求 13 §3.1 一致）

| 状态 | 含义 | 表现 |
|---|---|---|
| ok | 正常、在线、已验证、已发送、已接通 | 实心圆点 + 文字 |
| warn | 需关注、拨号中、振铃中、需实测、未接 | 实心圆点 + 文字 |
| err | 离线、失败、拒绝 | 实心圆点 + 文字 |
| unk | 未知、已过期、不适用、待验证、结果未知 | 空心圆点 + 虚线边框 + 文字 |
| live | 通话中 | 圆点脉动——**全站唯一的持续动效** |

- 状态**不能只靠颜色**：形状 + 文字。
- 每个状态附更新时间；过期显示 unk“未知 · N 分钟前更新”，不沿用旧值。
- “在线”与“可通话”分开显示。
- 业务状态到语义的映射（统一在 `lib/status-map.ts`）：

| 业务值 | 语义 | 文案键 |
|---|---|---|
| 设备 online / offline | ok / err | status.online / status.offline |
| SIM ready / absent / locked / unknown | ok / err / warn / unk | sim.ready … |
| Shizuku running / stopped / not_installed / unsupported | ok / err / err / unk | shizuku.* |
| 短信任务 queued / dispatched / accepted / sent / delivered / failed / unknown | warn / warn / warn / ok / ok / err / unk | sms.state.*（含“设备已接收”= accepted） |
| 腿 dialing / ringing / connected / ended / failed / unknown | warn / warn / live / unk / err / unk | leg.* |
| 通道 logged_in / login_pending / logged_out / offline / banned / error | ok / warn / unk / err / err / err | channel.* |
| 探测 ok / fail / untested / unsupported | ok / err / unk / unk | probe.* |

## 4. 页面框架

```text
┌───────────────────────────────────────────────────────────────────────────────┐
│ 顶部状态条：QQ ● 已登录·已配对·来电平台   TG ● 已登录·已配对   告警 2   通话中 1 │
├────────┬──────────────────────────────────────────────────────────────────────┤
│ 导航栏 │  页面标题                                          主要操作按钮      │
│ 仪表盘 │──────────────────────────────────────────────────────────────────────│
│ 设备   │                                                                      │
│ 短信   │  内容区（表格占满宽度；表单最大 640px）                               │
│ 通话   │                                                                      │
│ 通道   │                                                                      │
│ 指令   │                                                                      │
│ 告警   │                                                                      │
│ 设置   │                                                                      │
│ 日志   │                                                                      │
└────────┴──────────────────────────────────────────────────────────────────────┘
```

- 顶部状态条全站常驻：两个平台通道状态、来电平台标记、未处理告警数、进行中通话入口；实时连接断开时变为 warn 并显示“实时连接已断开，正在重连”。
- 导航栏位置（侧边 / 顶部 / 图标导轨）由选定主题决定；组件 `NavRail` 支持三种布局，通过主题配置切换。
- 断点（需求 13 §3.5）：以 1440 设计，1280 完整可用；≤ 1180 双栏改单栏；≤ 860 导航改为顶部横向滚动；表格只在表格内横向滚动。

## 5. 页面规范

| 路由 | 页面 | 必备内容 | 主要操作 |
|---|---|---|---|
| /dashboard | 仪表盘（首页） | 指标：设备总数/在线/离线/暂停、能力等级分布、SIM 数、可短信、可通话、通话中；两个通道卡片（状态、配对用户、来电平台）；进行中通话（跳线图）；未处理告警列表（前 5 条） | 跳转 |
| /devices | 设备列表 | 每台设备一行/卡：名称、在线与最后心跳、能力等级徽标、各 SIM（号码 + 来源标签 + 运营商 + 状态）、网络、电量、Shizuku、暂停、通话开关状态 | 筛选、绑定新设备（弹窗：6 位码大字等宽 + 二维码 + 倒计时 + 安装说明） |
| /devices/:id | 设备详情 | 基本信息；卡槽（号码登记、默认卡、需复核提示与“已复核”按钮）；能力探测表（项目/结果/探测时间/说明）；USB 自启状态；最近事件时间线 | 改名、启停、通话功能开关（确认：已通过 G0）、重新探测、解绑（确认需输入设备名） |
| /sms、/sms/:threadKey | 短信 | 左：会话列表（对方号码、设备/卡槽、摘要、时间）；右：消息流（入站左、出站右，出站带状态胶囊） | 发送：选择卡槽（显示号码）、正文、实时字数与分段数 |
| /calls、/calls/:id | 通话 | 进行中通话（跳线图）；通话记录表（类型、设备/卡槽、对方、平台、开始、时长、结果、是否播放“接通中”、是否透传回铃）；行展开事件时间线 | 拨号面板（选卡槽、号码输入实时解析提示、拨号）；通话中：计时、挂断、拨号键盘 |
| /channels | 平台通道 | QQ、Telegram 两张卡片：登录 · 消息 · 语音（已验证/未验证）· 配对用户；顶部单选“来电平台” | 登录（QQ 二维码；TG 手机号→验证码→二步密码分步表单）、登出、生成配对码（弹窗：8 位码、倒计时、“先互加好友，Telegram 需允许其来电”说明、复制）、解除配对、标记语音已验证（确认：已通过 G2/G3） |
| /commands | 指令记录 | 时间、平台、原文、解析结果、拨出卡槽、目标、状态、回复（可展开） | 筛选 |
| /alerts | 告警 | 页签：未处理 / 已确认 / 已解除；严重度、类型、对象、首次/最近时间、是否已推送 | 确认 |
| /settings | 设置 | 分组：通用（默认设备、界面语言、主题浅/深）· 机器人（回复与提示语音语言、短信转发）· 计时（来电振铃、回拨振铃、回拨等待、被叫等待、心跳、离线判定）· 短信（速率，可关闭）· 账号（修改密码） | 每组独立保存 |
| /audit | 操作日志 | 时间、操作、对象、详情展开 | 筛选 |
| /login | 登录 | 用户名、密码、语言选择；锁定时显示剩余时间 | 登录 |

## 6. 跳线图（PatchView）

```text
 蜂窝腿                          网关                          平台腿 / 浏览器腿
 +86 138 0013 8000  ─────────  [Z20 · 卡槽1]  - - - - - - -  QQ · 张三
 ● 已接通 02:31（live 脉动）                                  ● 振铃中 · 接通中提示播放
```

| 腿状态 | 线条 | 语义 |
|---|---|---|
| dialing / ringing | 静态虚线 | warn |
| connected | 实线 + 端点圆点脉动 | live |
| ended | 实线，降低不透明度 | unk |
| failed / unknown | 断开线段 | err / unk |

- 网关节点旁显示附加标记：“回铃透传”（转发早期媒体）或“接通中提示”（播放提示语音）。
- 只有 live 圆点有持续动效；`prefers-reduced-motion` 时圆点不脉动。
- SVG 绘制；每条腿同时输出读屏文本：“蜂窝腿：已接通，2 分 31 秒；平台腿：振铃中”。

## 8. 交互规则

- 实时数据经 /ws/admin 更新；断线时顶部状态条提示，数据旁显示过期标记。
- 首次加载骨架屏；操作按钮内加载态；不用全屏遮罩。
- 危险操作（解绑、解除配对、登出通道、挂断、开启通话功能、标记语音已验证）使用危险色并与普通操作分开摆放，需确认。
- 错误：后端错误码 → `errors.<CODE>` 文案，显示在字段下方或 Toast；不显示堆栈。
- 新短信、新告警：导航徽标计数；只用一个 `role="status"` 区域播报（“新短信 1 条”）。
- 键盘：全部可操作；焦点环清晰可见；弹窗焦点陷入并在关闭后返回触发元素。
- 时间：列表相对时间，悬停绝对时间（24 小时制，浏览器时区）。
- 触控目标 ≥ 32 px；间距 ≥ 8 px。

## 9. 文案规范

- 用管理员能理解的词：“卡槽”“来电平台”“配对用户”“接通中提示”，不说 subId、adapter、leg。
- 状态词固定词表，三语一一对应（i18n common 命名空间）。
- 按钮用动词：“绑定新设备”“生成配对码”“拨号”“挂断”。
- 错误写原因与下一步：“设备离线，无法发送。设备恢复在线后可重试。”
- 英文句首大写；英文长度预留 +40%；繁体用香港用语（短訊、來電、流動電話）；号码与编号不翻译。

## 10. APK 界面（需求 13 §3.6）

原生 View + AppCompat；颜色令牌映射到 colors.xml；系统字体；阴影在 API 19 用 layer-list；VectorDrawable 兼容；动效只用于状态变化与通话中；触控目标 ≥ 48 dp。界面：绑定、运行状态（连接、各能力、Shizuku 状态与指引、暂停大开关）、能力探测。
