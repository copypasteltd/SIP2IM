# QQ / Telegram 消息发起手机外呼方案（无 SIP）

> 2026-11-20 现行需求稿；未实际部署或呼叫。

## 1. 消息语法与身份

已配对用户向对应 QQ/TG 桥账号私聊发送：

| 格式 | 效果 |
|---|---|
| {目标号码} | 立即通过管理员配置的默认设备及 SIM 拨目标号码 |
| {拨出号码}/{目标号码} | 以左侧已登记 SIM 号码唯一匹配设备/SIM，立即拨右侧目标 |

按稳定平台 sender ID 识别已配对用户；一次性配对成功即获得来电与消息外呼完整授权，不要求二次确认。群聊、转发及重复事件默认拒绝；号码国家区号按实际地区设定，未知/重复 SIM 号码、默认设备未配置、离线或忙线时拒绝，不擅自切换。上游消息适配器是否能提供可靠 ID 和唯一事件需要验证。

## 2. 顺序与呼叫状态

用户 U 发消息 → 校验身份/号码并占用设备 → 安卓 SIM **先发起蜂窝外呼**至电话目标 B → 系统向原消息发送者 U 发起 QQ/TG 原生一对一语音回拨 → U 与 B 均实际接听后媒体双向桥接。控制/音频经无 SIP 自建连接实现，技术栈与平台兼容性未验证；不能将平台消息或音频消息当作原生实时通话。

状态：received → authorized → device_reserved → cellular_dial_submitted → platform_dial_submitted → 等待两端 connected → bridged → ending → ended，失败/不可确定转 failed 或 unknown。蜂窝拨号已提交但结果不明时不自动重新拨号；依原 request_id 和平台/设备 call_id 对账。

| 事件 | 处理 |
|---|---|
| B 先接，U 未接 | 可能开始计费；初始建议等 15 秒或 U 拒接即尽快结束蜂窝，具体以实测和配置为准 |
| U 先接，B 未接 | 初始建议最多等 30 秒；提示音可能自行生成，不当作真实运营商回铃 |
| U 拒接/离线/平台失败 | 尽快结束蜂窝腿，确认终态；未知时保留锁告警，不承诺零费用 |
| B 拒接/忙/失败 | 结束平台腿，向 U 显示可证实的原因；不把未知状态伪装为忙线 |
| 任一侧挂断/崩溃/事件重复 | 幂等终止另一侧和媒体，对账后释放设备；不盲目拨号 |

## 3. 费用、安全和媒体

用户确认消息即拨号，不添加二次确认。限制紧急及高风险号码、频率及费用，详细地区由管理员配置；先拨蜂窝意味着被叫可能先接、话费可能产生。默认每手机一通；只用获授权专机与平台账号。永久保存业务记录且不做脱敏；密码、平台 session、验证码不写入日志。媒体桥可接触音频，默认不录音、不转写。

## 4. 验收

分别在 QQ 和 Telegram 上验证私聊消息、平台 sender ID、两个号码格式、默认 SIM、重复号码拒绝、蜂窝先拨时序、原发送者回拨、双向声音、两端结束、单边先接、超时、断网、重复消息与 unknown 对账。至少 3 台设备管理并设计支持 20 台以上；实际并发和号码地区待定。具体无 SIP、MIT 兼容音频/平台实现尚待验证，不能将已过时的 SIP 机制当作当前方案。
