# Admin 管理体系与设备运营需求

> 当前版本：2026-11-20；仅一位管理员；无 SIP；无备份要求。手机与平台能力尚未实测。

## 1. 设备总览与统计

展示已绑定、启用、心跳在线/离线/未知、设备数量、SIM 数、短信收/发能力、电话控制、双向音频验证、忙线、QQ/TG 路由及异常。每个统计口径有更新时间；双卡一台手机计一台，SIM 分别计数；状态过期为未知，不把心跳在线等同电话可用。初始心跳 30 秒、90 秒未到标离线，按实际情况可配置。

## 2. 设备及 SIM 生命周期

管理员创建短期一次性绑定码 → 手机本机确认 → 登记独立设备凭据 → APK 上报快照和事件 → Admin 显示设备与 SIM。码应高熵、过期、限次、原子消费，设备可撤销。重装、换卡或密钥丢失不能自动按电话号码接管旧身份；管理员重新绑定并关联历史。解绑禁止新任务，进行中通话按状态清理，结果未知留待对账。

| 详情 | 信息 |
|---|---|
| 设备 | 显示名、ID、分组、机型、Android/ROM、APK 版本、最后心跳 |
| 网络 | 连接、网络类型、上报与服务器接收时间、状态 TTL |
| SIM | 槽位、subscriptionId、运营商、号码、号码来源和验证状态；因权限或系统原因可未知 |
| 短信 | 接收/发送授权、模块状态、队列、最近结果 |
| 电话 | Shizuku、通话控制、音频测试、忙闲与错误；每设备初版一次一通 |
| 平台 | QQ/TG 登录、消息、配对、原生通话及媒体验证分别呈现 |
| 健康 | 电量、充电、信号，温度按可取得情况；不采集位置、IMEI/IMSI/ICCID |

号码允许管理员人工登记，标明未验证；不能修改真实 SIM 号码。设备可上报号码但不能视为已验证；未获授权不自动发送短信或拨号验证。SIM 号码不唯一、未知、已变化或匹配冲突时拒绝指定号码外呼。

## 3. 单管理员管理能力

管理员可以登录、绑定/禁用/解绑设备、编辑名称分组和 SIM 号码、配置默认 SIM、QQ/TG 桥账号与目标路由、查看完整 SMS 与通话状态、发短信和拨号、查看完整业务记录与告警。单管理员不设 RBAC、多用户审批；保留管理员认证、设备凭据、配对用户身份以及操作日志。远程 APK 升级、任意 shell、静默重启、定位和录音不纳入首版。

## 4. QQ/TG 登录和用户配对

每个平台先用一个专用桥账号；Admin 提供登录、重登录、登出和状态。QQ 扫码/Telegram 普通用户登录依实际适配器能力实现，凭据/session 不写公开日志。账号在线、消息可收、目标配对、语音可拨、双向音频已验证是不同状态。

管理员在后台选择桥账号和设备/SIM 范围，生成一次性配对码（建议 5 分钟、5 次尝试）；目标用户向同一桥账号私聊发送。系统以平台事件验证稳定 sender ID 和私聊上下文，原子消费码后立即配对生效，无管理员二次确认；配对获得来电接听及消息外呼完整授权。支持管理员解除配对并阻止新呼叫。不得把昵称当身份；平台实际可获得字段和语音目标映射须 POC。截获配对码的第三方可能抢先获得授权，配对码应安全交付。

绑定成功不自动证明平台通话可用，允许一目标接多台设备；每 SIM 默认一个主目标，不并行自动回退。账号更换或失效时冻结相关路由并提示。

## 5. 短信、呼叫与路由

短信界面展示完整原始业务内容和状态，不脱敏、不自动删除。电话界面显示来电/外呼及各腿状态。QQ/TG 配对用户可发送 {拨出号码}/{目标号码} 指定 SIM 号码，或 {目标号码} 使用默认设备；消息即触发外呼，无二次确认，先蜂窝拨号再平台回拨。收到来电时先呼叫已配对目标；目标未接不接蜂窝。单设备占线、错误提示、未知状态对账和后台变更审计参见 [总体需求](需求梳理与解决方案.md)。

## 6. 告警、数据与远程命令

分别告警设备掉线、SIM 异常、短信权限、Shizuku、电话控制、QQ/TG 账号/消息/媒体状态及电量；可在后台查看，可选 QQ/TG 通知。业务记录永久保存不脱敏，无备份要求；凭据不写日志，禁止将密码/验证码/session 放入代码。关闭 CORS、不配置 TLS 由用户决定并自行处理公网代理；依然保留管理员会话和设备认证。

远程命令仅包括已实现的绑定、配置、启停和路由；使用 request_id、版本、过期时间及幂等处理，区分 accepted/applied/failed/unknown；短信/外呼结果未知不盲重试。

## 7. 初始数据与接口草案

Device、DeviceCredential、SimSubscription、SimNumber、StatusSnapshot、SmsMessage、SmsSendTask、CallSession、CallLeg、PlatformAccount、PairingRequest、PlatformIdentity、TargetBinding、RoutePolicy、Alert、AuditEvent。号码有来源与验证时间，不作为安全身份。候选 HTTP API：设备绑定/列表/详情、SIM 号码、短信、电话、平台登录、配对码、路由和告警；具体路径和消息字段待实现设计，不能视为已存在。

## 8. 验收

至少 3 台真机设备管理、SMS 及状态；容量设计覆盖 20 台以上。核验 SIM 数不等于设备数、号码未知/重复、设备重装/换卡、旧心跳、双卡映射、平台配对码过期/并发抢用/撤销、登录失效、目标身份与媒体状态、拒接/超时、消息重放、断网/服务重启、未知状态处理、双向通话与用户数据长期保存。容量及连续通话数尚未给定，不虚构通过结果。
