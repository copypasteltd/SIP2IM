| U02 | ~~服务器信息~~ 已于 2026-11-20 只读探测完成：Ubuntu 22.04.5、x86_64 i5-12400、62 GiB 内存、根分区剩余约 9.7 GB（90% 已用）、无 PulseAudio、systemd degraded | 新增待决：是否为本项目清理/扩容磁盘；详见 [可行性评估报告](可行性评估报告.md) |
| U07 | 每个平台准备几个桥账号（决定 QQ/TG 同时桥接通话数） | 一个账号通常同一时间一通；默认一个账号即全系统各 1 通 |
| U08 | MIT 约束下 QQ 无法实现时：放弃 QQ，或允许 GPL 组件作为可选插件 | QQ 现有实现均为 GPL 且仅 ARM64 验证，服务器为 x86_64 |

| U06 | 本地浏览器访问时如何取得浏览器认可的安全上下文：用户自有 HTTPS 代理、localhost 或其他可用方式 | 用户指定不由项目配置 TLS，普通局域网 HTTP 的浏览器麦克风可能无法使用 |

## 二、已接受推荐但仍需落实的参数/事实

| 编号 | 当前选定初始策略 | 待验证或补全 |
|---|---|---|
| V01 | 配对码 5 分钟、5 次尝试，一次使用；成功立即生效并获得完整来电与消息外呼授权 | 安全码交付及平台用户 ID 可靠性；撤销和绑定范围 |
| V02 | 设备心跳 30 秒、90 秒判离线 | 待各 ROM/Doze 和移动网络条件测量；功能状态独立过期 |
| V03 | 入站平台振铃 20 秒；一个 SIM 一个主目标，不并行/自动备用 | 运营商振铃窗口、实际主叫取消及可靠清理 |
| V04 | 出站被叫先接用户未接等待 15 秒；用户先接被叫未接等待 30 秒 | 计时起点、运营商表现和回拨能力实测；可能话费 |
| V05 | 初测单卡、模型预留双卡；不默认历史短信/MMS/RCS | 第一个设备与版本真实权限及需要的双卡验收范围 |
| V06 | 桌面 Chrome/Edge 浏览器通话；录音/转写/AI 不纳入首版 | 浏览器版本、音频/网络链路、安全上下文以及 DTMF 如需实际验证 |
| V07 | 后台告警优先、QQ/TG 通知可选 | 通知是否启用与其适配能力，且不得假设平台通知已实现 |

## 三、工程与许可证验证，不要求用户代做

| 编号 | 验证项 | 当前状态及退出条件 |
|---|---|---|
| T01 | 免 Root、无外接硬件、无 SIP 的通话音频 | 独立 MIT 方案尚未完成；分别验证蜂窝上行注入、下行捕获、真实双向音频及 Shizuku 失效处理。普通捕获权限不能证明上行注入。 |
| T02 | 延迟接听 | 无 SIP 自建状态机必须证明平台未接时蜂窝没有应答；用户不要求围绕运营商费用增设功能，但实测如实记录。 |
| T03 | QQ 原生一对一语音和消息身份 | 官方消息 API 不能证明原生通话；找到与 MIT 目标兼容的依赖、目标系统版本并完成真实账号双向测试。 |
| T04 | Telegram 私聊主动电话及音频 | Bot API 与 MTProto 用户账号能力不同；固定版本验证主动呼叫、双向音频及目标 ID。 |
| T05 | MIT 开源与依赖 | 项目代码 MIT 不能改变依赖许可证；GPL 上游不可直接改标 MIT；严格范围及第三方许可逐项清单和法律审查。 |
| T06 | 浏览器语音 | 用户自行处理外部 HTTPS；WebRTC DTLS/SRTP 等协议内建安全机制与自建 TLS 证书是不同事项，实际互通测试。 |
| T07 | 3 台真机和 20 台以上连接 | 需设计可复现容量及故障测试；同时通话指标待 U04，不能以设备数估算。 |
| T08 | 无备份与永久业务数据 | 按用户选择不构建备份、不脱敏；预估磁盘增长和故障导致不可恢复，保护密码/session 等凭据。 |
| T09 | 平台配对码泄漏 | 用户选择配对即生效且完整授权；通过短期一次性码、限次和撤销降低风险，不能消除被抢先配对风险。 |

## 四、范围与授权

用户要求无需二次确认配对/去电；对明确有效的配对和消息直接执行是产品要求。真实账号操作、真实电话测试及生产部署需按实际任务和用户授权执行；不在此擅自发起。禁止本地 Docker/WSL/虚拟化，旧 SIP 文档及 GPL 架构均不再作为实现方案。
