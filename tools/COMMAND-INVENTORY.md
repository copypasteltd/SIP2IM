# Offline command inventory

Run native Python 3 against two caller-supplied local, quiescent, checkpointed SQLite **copies**:

`python tools/command_inventory.py --gateway path/to/gateway.db --ledger path/to/command_ledger.db --assert-quiescent`

The assertion is the caller's responsibility; the tool cannot stop or identify writers, verify copy provenance, or establish a cross-database atomic snapshot. A WAL or rollback journal can contain committed or recovery data missing from the main file. This tool rejects a nonempty adjacent WAL or rollback journal before and after inspection. It uses SQLite immutable read-only mode and therefore does not read WAL contents or create SQLite sidecars. Prepare complete, consistent, checkpointed copies by an independently appropriate method; merely copying a live main file, or omitting sidecars, does not establish completeness. Do not point it at live databases. Hashes and file metadata before and after inspection detect some changes, not all races or changes between capture of the two files.

JSON on stdout contains full observed identity evidence, including SMS payloads, phone numbers and message bodies, ACK payloads and configuration values. Protect stdout and any redirected file with suitable access controls. SQLite BLOB values use base64 and non-finite REAL values use a tagged string. The full result is held and serialized in memory before writing stdout; large databases require corresponding memory. Output I/O failures may still truncate redirected output. Null and empty values remain distinct. No output file is opened by the utility. Inspect source paths and output destination carefully.

The report preserves all selected rows of sms_command, sms_task, acknowledgments and config, and records table/column coverage and user_version. Missing tables or columns are explicitly incomplete, never silently empty. Older ledger versions may lack command_type, payload or config; those identities remain unknown. It flags null/malformed command and task IDs against current Android handler patterns and exact same-string SMS command or task command-ID / ACK collisions, including malformed strings. A null SMS task link can be legitimate for rejected commands; a flag is evidence, not a verdict. It does not infer payload equivalence, decide task executability, migrate data, inventory outbox or sms_part, or recover ACKs evicted by the 500-row retention limit. Other columns and tables are outside coverage. The selected_columns_read flag means only that the selected columns were read; it does not validate schema constraints or versions, history, quiescence, or provenance. user_version is reported as observed without inferring compatibility. Any read or sidecar failure exits nonzero without a report.

Run tests from the project root: `python -m unittest discover -s tools -p test_command_inventory.py -v`. Tests create only synthetic databases in temporary directories under tools.
